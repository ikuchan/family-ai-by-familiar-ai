# familiar-ai 設計方針：パジュの状態（v0.1）

> **パジュの状態**（耳、頭、口、体がいま何をしているか）を、1 つの状態図で持つための設計方針（環-aw、2026-11-04〜06、本人の決定ア〜シ）。
> **実装はこれから。** 表の「いまの持ち主」は 2026-11-06 のコードの事実で、「決めた形」はこれから作る形である。
> 本人の指示は「パジュにたった一つの状態を持たせてください。そして、さまざまなイベントに対して、状態の変化を管理するようにしてください」「この仕組みは claude.md に記載する根源的な仕組みにしなさい」。

## 1. 1 つの状態図にする理由

パジュの状態は、いまは別々の器に散らばっている。黙る依頼は `agent_state` の `silence_request`、名前で開く窓は `WakeWindow`、仮の呼びかけは `_tentative_call`、待ちの電子音は `_deaf_while_beeping`、調べもの中は `Lookup.in_flight`、確認待ちは `confirm_frame` が持つ。縛り合う 2 つの状態は、片方の持ち主がもう片方を覗いて合わせている。

このため、どちらかが先に変わると、そのあいだだけ 2 つが食い違う。§5 の 6 件は、どれもこの食い違いが実機で表に出たものである。たとえば 10/18 には、確認を聞き返しているあいだに窓が閉じ、名前の無い「はい」が捨てられた。

そこで、パジュの状態を 1 つの**状態図**（Statecharts）にまとめ、状態を変えるのは**事象**だけにする。事象とは、パジュの状態を移すもの（声が届いた、話し終えた、タイマーが鳴った、など）である。状態図の書き方は Harel（1987）が考え、W3C SCXML が決まりにした[^statecharts]。

[^statecharts]: D. Harel, "Statecharts: A Visual Formalism for Complex Systems", Science of Computer Programming 8 (1987)。W3C, "State Chart XML (SCXML): State Machine Notation for Control Abstraction" (2015)。仕組みの先例は `モジュール分割設計` v0.43 の行 271 にある。

## 2. 状態図の形

状態図は、同時に動く 4 つの**並行の領域**（耳、頭、口、体）を持つ。**領域**は、同時にどれか 1 つの状態だけを取る区切りである（決定ア、イ、ウ）。口の中は、さらに 2 つの**入れ子の領域**（声と歌）に分ける（決定オ）。音楽を鳴らすことは、パジュが声を出して歌っていることと見なす。

領域どうしの同期は、Statecharts の決まりにそろえる（決定エ）。

- **一斉配信**：1 つの事象を、すべての領域へ同時に届ける。
- **移りの中で事象を起こす**：移りの途中で新しい事象を起こし、ほかの領域を動かす。
- **一歩を最後まで**：1 つの事象による移りを全部やり終えてから、次の事象を受ける。途中の食い違った状態は、外から見えない。
- **入るときの動作、出るときの動作**：ある状態に入るとき、出るときに、必ず行う動作。
- **禁止の条件**：ほかの領域の状態を見て、移りを止める条件。ほかの領域を条件に見るのは、禁止のときだけにする。

周りの事実は、状態図の状態にしない。移りを決める条件として読む（決定ア）。周りの事実は、タイマーが動いているか、在席と顔ぶれといまの話者（話者は 60 秒で切れる）、静穏時間、夜、カメラが使えるか、である。気分（P、A、Dom）と欲求（SEEKING、REST、BOND など）は数値なので、これも状態にしない。

## 3. 領域ごとの状態

### 3.1 耳

| 状態 | いまの持ち主 | 入る、抜ける |
|---|---|---|
| 閉じている | なし | 窓が切れると戻る |
| 窓が開いている | `WakeWindow`（`core/wake_window.py`、長さ 10 秒は行 19 の `WAKE_WINDOW_SEC`） | 名前で呼ばれると開く。時間で閉じる |
| 仮の呼びかけ | `_tentative_call`（`loop/event_loop.py:924`） | 値の足りない名前だけの声で入る。続く声で受けるか、消える |
| 黙っている | `silence_request`（`silence_state.py`） | 「黙って」かタイマーで入る。期限か解く言葉で抜ける |
| 電子音のあいだ聞かない | `_deaf_while_beeping`（`loop/event_loop.py:1813`、毎回その場で判定） | 合図が鳴ると入る。答えの声が始まると抜ける |

タイマーで黙るのと「黙って」で黙るのは、同じ「黙っている」である（情-u の決定エ）。黙っているあいだに窓を開けるのは、名前と一緒に言われた解く言葉を聞いたときだけにする（決定ケ）。名前だけの呼びかけでは窓を開けず、仮の呼びかけとしても預けない。いまのコードも同じ動きである（`loop/event_loop.py:4779-4794`）。

### 3.2 頭

| 状態 | いまの持ち主（`loop/event_loop.py` の行。ほかは file 名を書く） |
|---|---|
| 何もしていない | なし |
| 宛先を確かめている（家族どうしの話か、1 字違いの名前か） | `_between_family`（5201）、`_near_name_is_for_me`（5242） |
| 思い出している | `loop/iteration.py` の `_intake`、`_recall_at`（2937） |
| 決めている（調停） | `loop/iteration.py` の `_decide` |
| 書いている（主LLM） | `_run_main_llm`（1922） |
| 言う前に確かめている、言い直している | `_speech_check_violation`（4394）、`_send_back_for_say`（4343） |
| 調べている | `_run_lookup`（2108）、`_run_deep`（2162）、`_run_widen`（2517） |
| 見ている（写真を撮って読む） | `_run_camera`（2587）、`_read_photo_into_state`（2651） |
| 返事を待っている（確認待ち、申し出の預かり、聞き取りの確かめ） | `confirm_frame`（`agent.py:873`）、`_offer`（`loop/request.py:132`）、`_heard_check`（919） |
| 寝ている | 内省（`loop/rest.py`、起動は `loop/tonic.py:487-493`）、版の保存（`_write_version_later`、1285）、最終版（`_write_final`、1109）、言ったことの畳み（`_fold_told`、1521） |

**寝ている**は、書き留めをしているあいだの状態である（決定カ、キ）。書き留めは頭の仕事で、内省、版の保存、最終版を含む。版の保存は、頼まれごとをこなしながら「いま何を頼まれていて、どこまで進んだか」を頭の中で言い直して覚えておく動作に近い。それでも寝ているに入れるので、保存のあいだ頭は次の求めへ進まない。声が最大 0.8 秒ほど待たされることは受け入れた（10/13 00:35 の実測。いまは裏で書いてこの待ちを避けている）。

寝ているあいだも、耳は開けておき、聞いた言葉は預かる（決定ク）。版の保存と最終版は、書き終えてから起きて答える。内省は、いまの層を終えたところで止めて起き、残りの層は次の回へ持ち越す。

### 3.3 口

口は、入れ子の領域「声」と「歌」を持つ。

| 領域 | 状態 | いまの持ち主（`loop/event_loop.py` の行） |
|---|---|---|
| 声 | なし | なし |
| 声 | 話している | `_speak`（4613）、`_say_aloud`（5512） |
| 声 | 合図、電子音 | `_beep_while_waiting`（1787） |
| 声 | タイマー、アラームの音 | タイマーの側 |
| 歌 | 止まっている | `_music_status`（3507）が毎回、再生の機器から読む |
| 歌 | 鳴っている | 同上 |
| 歌 | 絞っている | 音楽の側で持つ |

### 3.4 体

| 状態 | 文書 | 入る、抜ける |
|---|---|---|
| 止まっている | なし | なし |
| 首を動かしている | `設計図_Mermaid` の [D-向き]、`設計詳細_活性_O書込_知覚在席` v0.41 | `look` や見回りの 1 歩で入る。揺れが収まると抜ける |
| 見回っている | ユースケース③ v0.5 | 欲求の発火で入る。1 歩終わる、人が来る、話しかけられると抜ける |

## 4. 縛り合う組と同期

「同期の与え方」の列は、決定エの決まりを組ごとに当てはめたものである。組ごとの割り当ては、実装計画の段でもう一度確かめる。

| 組 | 縛り | いまの持ち方 | 同期の与え方 |
|---|---|---|---|
| 声の合図、電子音と耳 | 電子音のあいだは、名前があっても声を捨てる（出-dd） | `_deaf_while_beeping` が毎回、電子音の仕事が生きているかを見る | 声が合図、電子音に入るとき、移りの中で事象を起こし、耳を電子音のあいだ聞かないへ移す。出るときに戻す |
| 頭の決めていると、声の電子音 | 声で始まった求めの判断が始まると鳴らし、最後の動作が決まったら止める（出-dc） | `_beep_while_waiting` の仕事 | 頭が決めているに入るときの動作で、鳴らす事象を起こす。出るときの動作で止める |
| 声の話していると、耳の窓 | 話しているあいだは窓を閉じない。話し終わってから 10 秒は開けておく | `WakeWindow.hold`、`release`（`core/wake_window.py:211`、`219`） | 声が話しているに入るときの動作で窓を保ち、出るときの動作で 10 秒を数え始める |
| 頭の返事を待っていると、耳の窓 | 確認を聞いたら、話し終わってから 10 秒は窓を開ける | 窓の側で開け直す | 頭が返事を待っているに入るときの動作で、窓を開け直す事象を起こす |
| 耳の黙っていると、声 | 黙っているあいだは話さない。タイマーが鳴った知らせだけは通す | `silence_request` と入口の門 | 禁止の条件：耳が黙っているあいだ、声は話しているへ移れない（タイマーが鳴った知らせを除く） |
| 声のタイマーの音と、声の話している | 同じ機器を順番に使う | タイマーの側で持つ | 同じ領域の状態なので、同時には成り立たない |
| 声の話していると、歌 | 話しているあいだは音量を絞る | 音楽の側で持つ | 声が話しているに入るときの動作で歌を絞っているへ、出るときの動作で鳴っているへ戻す（決定オ） |
| 体の首を動かしていると、在席の見方 | 動いているあいだは、在席と定点の「普通」を更新しない | 揺れの門（`設計詳細_活性_O書込_知覚在席` v0.41 の行 125、190） | 禁止の条件：体が首を動かしているあいだ、在席の更新をしない |
| 頭の調べていると、耳 | 調べているあいだに話しかけられたら、調べかけを打ち切る | `_abort_lookups`（`loop/event_loop.py:3216`） | 耳で声を受けた事象を一斉配信し、頭は調べているを出るときの動作で調べかけを打ち切る |
| 頭の寝ていると、耳 | 寝ているあいだも聞いた言葉は預かる（決定ク） | なし（内省は会話とは別の輪で回る） | 耳で声を受けた事象を一斉配信する。頭は、書き終えるか層の切れ目で寝ているを出てから受ける |

## 5. 実機でぶつかった事例

縛り合う 2 つの持ち主が食い違って起きた不具合のうち、課題として記録のあるものは 6 件である。

| 日 | 課題 | 起きたこと |
|---|---|---|
| 09-26 | 出-as | 「黙ってるね」と答えたのに、黙る状態が登録されなかった |
| 09-26 | 出-as | タイマーで耳は閉じたのに、口は開いたままで話しかけた |
| 10-18 | なし（窓の直し） | 確認を聞き返しているあいだに窓が閉じ、名前の無い「はい」を捨てた |
| 10-31 | 出-dg | 申し出への「はい」が、状態を伝える返事になった |
| 11-03 | 出-dl | 調べものが立っていないのに「お待ち」と約束した |
| 11-03 | 情-u | 黙っているあいだ、名前つきの頼みが合図なしに消えた |

## 6. 決定

| 記号 | 決めたこと |
|---|---|
| ア | 状態の入れ物は 1 つ。周りの事実は状態にせず、移りの条件として読む |
| イ | 体の領域を持つ（止まっている、首を動かしている、見回っている） |
| ウ | 領域は耳、頭、口、体の 4 つ。縛り合う組には、設計の上ではっきりした同期を与える |
| エ | 同期は Statecharts の決まり（一斉配信、移りの中で事象を起こす、一歩を最後まで）にそろえる。ほかの領域を条件に見るのは禁止の条件だけ |
| オ | 口を入れ子の領域「声」と「歌」に分ける。音楽を鳴らすことを、パジュが歌うことと見なす |
| カ | 書き留めは頭の仕事で、寝ているのと同じ |
| キ | 内省だけでなく、版の保存と最終版も寝ているに入れる。声が最大 0.8 秒ほど待たされるのは受け入れる |
| ク | 寝ているあいだも耳は開け、聞いた言葉は預かる。版の保存と最終版は書き終えてから、内省はいまの層を終えてから起きる |
| ケ | 黙っているあいだ、窓は名前と一緒に言われた解く言葉のときだけ開ける |
| コ | この文書を作り、課題8 と索引からリンクする |
| サ | CLAUDE.md の開発ルールと完了条件に 1 項ずつ足し、状態の中身はこの文書に置く |
| シ | 用語一覧に「パジュの状態の語」の節を足す。状態を移すものは「事象」と呼ぶ |

## 7. まだ決めていないこと

- 状態図を、既存のライブラリで書くか、自分で書くか（ライブラリを足すなら依存の追加の承認が要る）。
- 家族が再生の機器で直接かけた曲も、パジュが歌っているに入れるか。
- 長い最終版を裏の列で要約する仕事（`_spawn_final`）を、寝ているに含めるか。
- 内省を層の切れ目で止めたとき、残りの層を次の回へ持ち越せるか（層ごとには、まだ読んでいない）。
- 「黙っていて」に返事をした直後に窓が開いたままのとき、名前の無い言葉がどう扱われるか（試していない）。
- タイマーやアラームの音が歌と重なったときの扱い（コードを読んでいない）。

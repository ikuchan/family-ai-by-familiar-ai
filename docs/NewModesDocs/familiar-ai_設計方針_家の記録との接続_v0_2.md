# familiar-ai 設計方針：家の記録との接続（obsidian-memo）（v0.2）

## この文書が決めること

`obsidian-memo` という MCP サーバーを通して、**家の記録**（Obsidian の Vault）を引く形を
決める。相手側の仕様書はこちらに置かない——**契約は実行時の `tools/list` にある**（起動して
叩けば `description` と `inputSchema` が読める）。ここに書くのは**こちら側の判断**である。

## 1. 何が繋がったか

**パジュの記憶とは別の蓄積である。**

| | 中身 | 誰が書いたか |
|---|---|---|
| `observations`（O） | 一緒に暮らした記憶。見たもの・感じたこと・会話 | **パジュ** |
| `obsidian-memo` | 積み上げた理解。3年ぶんの記録（約200万字） | **人**（本人と Claude Code） |

**二重にならない。** 向こうは会話を記録しない。**読まれるだけ**である。

置き場は **内部資源**（実行担当 TEX が呼ぶ）。外部の機械ではない——`stdio` で同じ機械の
サブプロセスとして立ち、物理世界に触れない（`設計図` v0.86「MCP も何に密着しているかで
置き場が決まる」）。

## 2. 道具は2本で、性質が正反対である

| 道具 | ティア | 速さ | 話者ゲート |
|---|---|---|---|
| `get_house_rules` | **家族** | **即座**（ファイルを読むだけ） | **要らない** |
| `ask_vault_yusuke` | **個人** | **数十秒**（Claude Code のセッションが読んで考える） | **要る** |

### `get_house_rules`

引数なし。家のいま有効な決まり（ゲームと YouTube をしていい曜日・1日の長さ・休憩・
帰宅時の3分の運動）を返す。返り値の先頭に **JST で今日が何曜日か、ゲームをしていい日か**が
入っているので、曜日を自分で数えなくてよい。

**返るのは Vault のファイルの中身であって、生成物ではない。** ルールが変われば次の呼び出し
から変わる。**いつ時点のものかが必ず添えられている。**

### `ask_vault_yusuke`

**検索ツールではない。** Vault を全部読める Claude Code のセッションが立ち上がり、読んで、
考えて、答える。セッションは**1日1本**で、**04:00 JST に切り替わる**（0時ではない——
22〜23時が本人の内省の時間で、その続きの深夜を前日側に残すため）。

**同期で待たない。** `search_deferred` / `fetch_deferred` に乗せる。数十秒かかるので、
待つと会話が止まる。

**返り値の末尾の `──（YYYY-MM-DD のセッション／継続）` は読み上げない。** 素性を示すための
もので、本人向けの情報ではない。

## 3. 話者ゲート ── こちら側の責任である

**★ サーバー側からは誰が話しているか見えない。** だからゲートは**こちらが掛ける**。

```
話者が Yusuke     →  get_house_rules ＋ ask_vault_yusuke
それ以外・不明     →  get_house_rules だけ
```

**規則は名前で決まる。** 個人ティアの道具名には人が入っている（`*_yusuke`）。
**名前に人が入っている道具は、その人のターン以外では出さない。** 将来 `*_taeko` が増えても
同じ規則で通る。

**`description` でお願いするのではなく、構造で落とす。** 存在しない道具は呼べない。
`ask_vault_yusuke` は Vault を**全部**読む——転職活動の悩み、人物評、家計、子どもについて
父が書いたこと。**子どもと話しているターンで、この道具が存在してはいけない。**

## 4. こちら側の現状（2026-09-04 に実測）

**★ 話者ゲートを掛ける場所が、まだ無い。**

申し送りは「`_build_tool_definitions()` が落とす」と書いているが、**その関数はこの
リポジトリに存在しない**（grep で0件）。道具が主LLM へ渡る経路は
`loop/event_loop.py` の `_ACTIONS` で、中身は6つに固定されている。

```python
_FULL_ACTIONS = ("say", "recall", "search_deferred", "fetch_deferred", "see", "look")
```

**MCP の道具はここに載っていない。** つまり現状、`get_house_rules` も `ask_vault_yusuke` も
**主LLM の道具一覧に現れず、呼べない**。呼ぶ経路（`agent.py` の `self._mcp.call`）はあるが、
名前を知らせていないので使われない。

**いまは事故にならないが、順序を間違えられない。** `_ACTIONS` に MCP を足した瞬間、
話者ゲートが無ければ `ask_vault_yusuke` が誰のターンでも見える。

**この節は着手前の実測である。**§5 の決定に従って `house_rules` を足したので、いまの
`_FULL_ACTIONS` は7つある。`_ACTIONS` の項目は `_mcp_tool_def(a, "get_house_rules")` で
名前を1つに絞っており、`ask_vault_yusuke` は項目そのものが無い。**構造で落ちている**ので、
`description` の書き方に依存しない（2026-09-04 に確認）。

## 5. 決めたこと（2026-09-04）

**`get_house_rules` だけを先に繋ぐ。** 話者ゲートの要らない家族ティアなので、いま繋いでも
安全である。子どもが「今日ゲームやっていい?」と聞ける状態を先に作る。

**`ask_vault_yusuke` は繋がない。** 話者ゲートと、遅延（`search_deferred` への相乗り）の
設計が決まるまで、道具一覧に出さない。**安全側に倒す。**

## 6. やらないこと

- **`ObsidianMemo` のリポジトリを直接触らない。** Vault の中身は向こうのセッションが維持
  している。読むのは MCP 経由でだけ
- **道具の名前を変えない。** 話者ゲートが名前に依存する
- **`capabilities.yaml` にルールの本文を書かない。** 実体は Vault にあり、実際に
  2026-09-01 に変わった。コピーするとそこが古くなる。**参照だけ書く**

## 7. 起動時のインタプリタ（未対応）

`~/.familiar-ai.json` の `command` は `"python"` である。**この機械に `python` は無く、
`/usr/bin/python3` だけである**（2026-09-04 に `command -v` で確認）。それでもいま上がるのは、
`uv run familiar` で起こすと `python` が `.venv/bin/python` へ解決されるためで、**起動の
仕方に依存している**。venv の外から起こせば上がらない。

確実にするなら `command` をフルパスにする。`memo_mcp` は依存ゼロなので venv を分ける必要が
なく、こちらの `.venv/bin/python`（3.11.16）でそのまま動くことは
`--selftest` で確かめた（`initialize` から `get_house_rules` まで1往復ずつ通った）。

**まだ変えていない。**実機まわりの作業として後回しにしている。

# familiar-ai 実機確認シナリオ：ループと記憶の口（v0.1）

## 目的

**知-c（昼夜の見回り）の実機確認**と、**2026-09-11／12 に入れた11の変更**を、同じ回で確かめる。

知-c は着手順の先頭に置いたまま進んでいない——実装は済んでおり、**首が実際に回ることを一度も
確かめていない**。そのあいだにループと記憶の口へ変更が積み上がり、**そのどれも実機を通って
いない**。全体テストは 2,590 件が緑だが、**テストが見ているのは呼び出しの形**であって、
首が回るか・返事が返るか・停止ボタンが効くかではない。

判定は「事実（画面・ログで見えたこと）」だけで下す。各シナリオに、**成り立つ場合に見える
もの**と**間違っていれば見えるはず**を対で記す。

## 0. 起動する前に——**本番 DB が起動と同時に変わる**

```python
# store/context.py  conn() の中
apply_migrations(conn, default_migration_dir())
```

**接続した瞬間に、未適用の 057・059・060 が本番へ当たる。** 「適用は人の手で」という申し送りは、
実際には**アプリを起動した時点で自動で当たる**形になっている。3本のあいだに依存は無く、
一括で当たってよい（057 は PAD を未測定へ戻すだけで、059・060 は PAD を見ない）。

**059 と 060 は列と表を落とす操作を含む。** どちらも自分で件数を突き合わせ、合わなければ
例外で止まり、落とさない。

|---|---|
| 059 | 列を落とす前に `observations_superseded_by_backup` へ控える |
| 060 | 元の2表を落とさず `wr_records_moved`／`wr_record_items_moved` へ改名して残す |

それでもバックアップは取る。**止まったあとの状態から戻る道が要る。**

## 2. 観測点を足す（終わったら外す）

いまのログでは見えないものが2つある。

| 見たいもの | いまの状態 | 足すもの |
|---|---|---|
| 記憶の申告 | **見える**（`event-loop 記憶の判定 N/M 件`・INFO） | — |

## 3. シナリオ

### A. 知-c：見回りで首が回る

- **操作**：部屋を無人にして待つ（自発の見回りを待つ）。待てなければ `look` を起こす
- **成立で見えるもの**：カメラが**物理的に動く**。`event-loop 出力=look（続きは完了で起きる）`
  → 次の反復で `見た` の記録 → 返事に見えたものが出る
- **間違っていれば見えるはず**：ログに `look` は出るが**首が動かない**（機器側）。
  または `look` が一度も出ない（起動源）

### B. 会話が成立する（環-f-い-2）← **いちばん危ない**

反復が**呼び手のタスクから駆動体へ移った**。呼び手は `Future` で待つ。

- **操作**：GUI で3往復。途中で**停止ボタン**を押す
- **成立で見えるもの**：返事が出る。停止で**その場で止まる**。止めたあとも**次の発話に応じる**
- **間違っていれば見えるはず**：
  - 返事が返らない → `push_utterance` の `Future` が解決していない
  - 停止しても喋り続ける → 待ち手の cancel が反復へ届いていない
  - 停止後に無反応 → 駆動体まで畳んでいる
  - `is bound to a different event loop` がログに出続ける → 待ち行列の作り直しが効いていない

### C. 主LLM の申告（出-h-い）

- **操作**：記憶に触れる問い（「運動会の話、覚えてる？」）
- **成立**：`event-loop 記憶の判定 N/M 件` の **N=M**（W に並んだ全件）
- **間違っていれば**：`N<M`（欠落）／`0/M`（申告そのものが出ない）

### D. 軽量LLM の申告（出-h-ろ）

- **操作**：短い受け答え（「ただいま」）を数回
- **成立**：`light` で閉じた反復のあとにも `記憶の判定` が出る。**返事は待たされない**
- **間違っていれば**：`light` のあとに判定が出ない／返事が1秒以上遅れる（背景に出せていない）

### E. 誰の記録か（記-f）

- **操作**：B のあと、W のログを見る
- **成立**：`ゆうすけが言った: …` と `わたしが答えた: …` が**分かれて**出る
- **間違っていれば**：`発話: …` のまま（`actor` の面が立っていない）／人の言葉に `わたし` が付く

### F. 待ち行列が1本（環-f-い-1）

- **操作**：**調べものを投げさせてから**（「今日の天気は？」）、すぐに部屋へ人が入る
- **成立**：調査中は入室が**待たされ**、調査が終わってから処理される。**取りこぼさない**
- **間違っていれば**：調査の途中に入室の話が割り込む／入室が**消える**

### G. キャッシュ（出-i）

- **操作**：5分以内に3往復 → 6分空けて1往復 → 終了
- **成立**：2往復目以降 `cache_read` が数千トークン。6分後は `cache_write`。終了時に例外が出ない
- **間違っていれば**：毎回 `cache_write`（前方一致が壊れている＝安定部か道具が毎回変わっている）

### H. 口を通る（環-e-い）

- **操作**：A〜G のあいだ、DEBUG ログを流し続ける
- **成立**：`OIF write/recall/link/actors` が出る。**記憶へ直に触るログは無い**
- **間違っていれば**：例外で OIF が落ちている（`writer_id` の必須化・`Recalled` への移行の取りこぼし）

## 5. 中止条件

- **B が破綻したら、そこで止める。** 会話が成立しなければ C〜H は測れない。
- **マイグレーションが例外で止まったら、そこで止める。** 本番への書き込みなので、
  原因の調査だけを行い、対処は承認を取ってから行う。
- **例外が出たら、その場でログを保存する。** 変更は11個あり、どれが原因かはログでしか
  分からない。

## 6. 総合判定

- A が成立すれば **知-c を実機了**とする（着手順の先頭がようやく進む）。
- B〜H が成立すれば、11の変更を**実機了**とする。
- 破綻が出たら、その事実（何がどの順で見えたか）を記録し、原因を切り分ける。
  値の調整は課題5、結線の誤りはコード修正へ戻す。

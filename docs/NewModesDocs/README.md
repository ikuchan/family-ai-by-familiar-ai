# familiar-ai 設計ドキュメント索引

`docs/NewModesDocs/` は、familiar-ai の設計と計画の正本を置く場所である。実装に手を付ける前に、触る領域の正本をここで確かめる。

各資料のファイル名と題に版は付けず、更新履歴の節も持たない。変わり目は git の履歴（`git log --follow <ファイル>`）で追い、何を変えたかはコミットのメッセージに書く（2026-11-23 から）。資料を書く・直すときは `.claude/rules/文章規範.md` に従う。

## 扱いの約束

- **正本を先に読む**。関連コードを触る前に、その領域の資料を読む。新しい設計・計画は必ずここへ書く（版の無い名前で）。
- **置き場は種類で決める**（環-as・2026-11-24）。この索引のほかは、名前の頭で次のフォルダに置く。一番上には置かない（`tests/test_docs_are_consistent.py` が確かめる）。
  - `進め方/`：直近の進め方と進捗・課題・gap分析・チケット・改造方針・不具合調査・ME と FAMILY の見直し
  - `全体/`：設計図・用語一覧・感情ループ全体像・モジュール分割設計・イベント駆動ループ・音声入力から GUI への経路
  - `設計方針/`：設計方針_〇〇
  - `設計詳細/`：設計詳細_〇〇・I内部設計根拠・拡散想起・MI データモデル
  - `ユースケース/`：ユースケース〇
  - `記録/`：計測_設定値根拠台帳・実機確認シナリオ・復旧記録
  文書どうしのリンクは、置き場からの相対の道筋で張る。コードの注釈は文書を名前（`設計方針_パジュの状態` など）で呼び、置き場は書かない。
- **`@import` で全部を取り込まない**。毎セッション読み込むには重い。必要なものを都度開く。
- **実装済みのことだけを書く**とは限らない。設計資料には未実装の決定が含まれる（`CLAUDE.md` は仕様を持たず、コードは実装済みのことだけを持つ。扱いが違う）。どこまで実装したかは、設計図の「store と I/F」台帳と、各実装記録の資料が持つ。

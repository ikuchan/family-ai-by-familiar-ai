# familiar-ai 設計方針：人物表と名前（v0.2）

人物表（`persons`）の鍵は `FAMILY.md` の**名前**である。人を指す言葉は、すべて `FAMILY.md` で名前に直してから、
人物表を名前の完全一致で引く。二重になった人物表は、記憶の付いた古い行を残して統合する。課題は `課題8` の知-af。

## 1. 目的

記憶の行き先を、`FAMILY.md` のいまの記述だけで決まるようにする。

本番の人物表は二重になっていた。記憶が付いているのは古い行（`いくながゆうすけ` 3,585 件ほか）で、いまの `FAMILY.md` が
作った行（`ゆうすけ` ほか）は記憶 0 件だった（2026-09-20 に本番 DB を読んで判明）。記憶の行き先は、次の 3 つが重なって
決まっていた。

- **別名で引いていた**：人を指す言葉を、人物表の `display_name`（呼び方）の別名とも照らしていた。
- **呼び方が古いまま**：登録は同じ名前の行があれば何もしないので、`display_name` は最初に登録したときのまま止まっていた。
- **並び順で選んでいた**：当たる行が複数あると、作られた順の最初の行を黙って選んでいた。

テンプレートの節から作られたゴミの人物も 2 件あった。「名前：」の後ろが空のとき、読み取りが改行をまたいで、次の行
（`- **呼び方**：…`）を名前として拾っていた。

## 2. 名前は 3 種類

| 種類 | どこに書くか | 使い道 |
|---|---|---|
| **名前** | `FAMILY.md` の「名前」 | 人物表の鍵。記憶はこの名前の行へ振り分ける |
| **呼びかけ名** | `FAMILY.md` の「呼び方」の先頭 | パジュが呼びかけるときの名前。話者の帳面にもこの名前で登録する |
| **呼び方の別名** | `FAMILY.md` の「呼び方」の一つずつ | 人を指す言葉を名前に直すための照合 |

`FAMILY.md` の欄は同じ行だけを読む（`core/parsing.py`）。空の欄は空のままにし、次の行を拾わない。

## 3. 引き方

人を指す言葉から人物を引く口は `PersonMemoryManager.find_person_id_by_name` の 1 つである（呼び手は変えていない）。

1. 言葉を `FAMILY.md` で名前に直す。名前・呼びかけ名・呼び方の別名のどれでもよい。
2. 人物表を、その名前の完全一致で引く。

- **照らさないもの**：人物表の `display_name` は照らさない。最初に登録したときのまま止まっていることがあるからだ。
- **当たらないとき**：`FAMILY.md` に無い言葉は、誰にも当てない（None）。
- **2 人に当たるとき**：誰とも決めず（None）、ログ（error）に残す。作られた順では選ばない。
- **`FAMILY.md` が無いとき**：名前の完全一致だけで引く。

人物表は `FAMILY.md` を、起動時と `/reload` に `set_family_md` で受け取る。

## 4. 起動時と `/reload` の検め

`FAMILY.md` の家族を人物表に合わせる（`agent._register_family_from_md`）。

- **名前の行があるとき**：呼び方（`display_name`）を `FAMILY.md` の呼び方に書き直す（`update_display_name`）。
- **名前の行が無く、呼び方が既存の行の名前か呼び方と重なるとき**：名前を書き換えたとみて、**新しい行は作らない**。
  作ると古い行と並び、記憶の行き先が分かれるからだ。統合のスクリプトを促すログ（error）を残す。
- **重ならない新しい家族**：いままでどおり行を作る。
- **2 人に同じ呼び方があるとき**：ログ（error）で知らせる。その言葉では誰とも決まらない。

## 5. 統合

二重になった人物表は、スクリプト `scripts/merge_persons.py` でまとめる（中身は `store/person_merge.py`）。ふだんは
人物表の行を消す・名前を書き換えるだけで、1 人に記憶の付いた行が 2 つ以上あるときだけ記憶を付け替える（v0.2）。

- **残す行**：記憶の付いた行を残し、名前と呼び方を `FAMILY.md` に合わせて書き換える（本人の決定ア）。記憶の付いた
  行が 2 つ以上あれば、記憶の付いた `FAMILY.md` の名前の行を、無ければ記憶の多い行を残す。
- **消す行**：記憶 0 件の重なった行と、テンプレートから作られたゴミの行（名前が `-`・`*`・括弧で始まる）。
- **記憶の数え方**：人物表を参照する外部キーを DB から読み、人物ごとに数える（いまは `memory_events` と
  `situated_memories`・`recognition_embeddings`）。表を決め打ちにしないので、スキーマが変わっても参照のある行を
  そのまま消さない。
- **付け替え**（v0.2）：1 人の家族に参照のある行が 2 つ以上あれば、残す行以外の行の参照を、人物表を参照するすべての
  表で残す行へ移し、移した行を消す。`situated_memories` は（記録・人・関係）で一意なので、残す行に同じ（記録・関係）が
  ある組は、移す行の分を先に捨てる。計画と結果に、移した数と捨てた数を出す。
- **行と家族の対応**：行の名前か呼び方が、その家族の名前か呼び方の別名に当たれば対応させる。比べる前に、カタカナを
  ひらがなに直し、末尾の敬称（さん・くん・ちゃん）を落とす（v0.2）。
- **止まるとき**（何も書かない）：参照のある 1 つの行が、2 人以上の家族に当たる。
- **残して知らせる行**：どの家族にも当たらない行は残し、計画に名前と参照の数を出す。
- **触らない行**：パジュ自身の行と、既定の人の行。
- **当て方**：1 つのトランザクションで、付け替える → 消す → 名前を書き換える の順（名前は一意なので）。

スクリプトは既定では計画を見せて巻き戻し、`--apply` を付けたときだけ書く。未適用のマイグレーションがあれば止まる。

### 5a. 本番の手順（本人が行う）

1. `FAMILY.md` の名前を、残したい名前（漢字など）に直す。統合はこの名前へ書き換える。
2. アプリを止める。
3. `scripts/backup_db.sh` で退避する。
4. `uv run python scripts/apply_migrations.py` で未適用を見る。あれば `--apply` で当てる。
5. `uv run python scripts/merge_persons.py` で計画を見る。よければ `--apply` で当てる。
6. アプリを起動する。

統合を当てるまでは、本番のアプリを起動しない。名前で引くと、記憶 0 件の新しい行に当たり、記憶がそちらへ書かれる。

### 5b. 本番で当てたこと（2026-10-05）

- **1 回目**：ゴミの行 2 つと記憶 0 件の行 3 つ（ゆうすけ・たいき・こうき）を消し、記憶の付いた古い行を書き換えた
  （いくながゆうすけ 5,053 件 → 雄輔・いくながたいき 1,022 件 → 泰輝・いくながこうき 127 件 → 航輝）。ママは、記憶の
  付いた行が 2 つあった（`いくながたえこ`「まま、たえこさん」43 件・`たえこ`「ママ」12 件）。呼び方の完全一致だけで比べて
  いたので、`いくながたえこ` は誰にも当たらず残り、`たえこ` だけが妙子に書き換わった（止まるはずの形が止まらなかった）。
- **2 回目**（v0.2 の付け替え）：`いくながたえこ` の 43 件を妙子へ移し（ぶつかって捨てた組 0）、行を消した。人物表は
  6 行（パジュ・既定の人・家族 4 人）になった。

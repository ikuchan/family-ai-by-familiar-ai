# familiar-ai 実機確認シナリオ：想起（Phase 2 P スライス）（v0.1）

> v0.1：Phase 2 の想起改造（入口 P）の実機確認シナリオ。P-1（活性の想起接続・importance 日次減衰の撤去）から起こす。以後の P-2〜P-4 でシナリオを追記する。

## 目的

想起スコアの改造は全体テストで回帰を防げるが、**想起順が体感として破綻しないか**は実データと実会話でしか見えない。本書は、各 P スライスの挙動変化を実機で確かめる手順と、**成り立つ場合に見えるもの／間違っていれば見えるはず**を対で記す。判定は「事実（画面・ログで見えたこと）」だけで下す。

対象アプリの起動は `./run.sh`。会話入力は `recall_async(user_input, recall_mode="conversation")` に流れ、その結果がフルLLM の文脈へ載る。よって「記憶を問う対話」を打ち、返答に現れる記憶と、想起ログ（`recall` の score 順）を見る。

**実施タイミング**：各 P スライスを打つたびに毎回は回さない。チャットレベルの改修（P スライス群）が一通り終わり、知覚（DIF・在席検出・話者帰属）を作る前の段階で、たまった P-1〜P-4 の挙動をまとめて実機で確認する。それまでは各スライスの全体テスト緑で回帰を担保し、本書に判定を溜める。

## 共通の前提と観測点

- **起動**：`./run.sh`。実データ（本番 DB の記憶）で行う。空の DB では想起の差が出ないため、日付にばらつきのある観測が数十件以上ある状態で行う。
- **観測点**：(a) 返答に現れる記憶の内容、(b) 想起ログの score 順（`recall` の返り値の `score`）、(c) 想起された記憶の日付。ログの粒度が足りなければ、`recall` 前後に一時的な debug ログを足して score・日付・a0・n を出す。
- **記録**：各シナリオで「見えたもの」を下の記録表に書き、成立／破綻を判定する。

## P-1：活性の想起接続・時間減衰の t 軸一元化

### 変えたこと（事実）

`_compute_final_score` の積を `importance` から `_derive_activation(activation_a0, activation_n)` へ替えた。あわせて `importance` の日次減衰（`_generate_day_summary` の `decay_importance`）を撤去し、時間減衰は `time_score`（t 軸）だけにした。n は当面 0 のため、a 軸は取込値 `activation_a0` の錨で効く。

### シナリオ 1：時間減衰が t 軸で生きているか

- **操作**：新しい話題と、明確に古い話題（数週間前の記憶に触れる問い）を続けて問う。例：「昨日の話をして」「先月の◯◯の話は？」
- **成立で見えるもの**：新しい記憶が古い記憶より上位に来る（score が高い）。古い記憶も沈みはするが完全には消えない（floor で下げ止まる）。
- **間違っていれば見えるはず**：古い記憶が新しい記憶より上位に来る／新しい記憶が想起されない。これが出たら t 軸（time_score）の結線が壊れている。

### シナリオ 2：二重減衰の撤去で古い記憶が沈みにくくなっていないか

- **狙い**：importance の日次 0.95 減衰を外したので、**以前より古い記憶がやや上がる**はず（時間減衰が二重から一重へ）。過度に上がって新しい記憶を押しのけないかを見る。
- **操作**：関連の強い古い記憶と、関連の弱い新しい記憶が競合する問いを打つ（話題語で古い記憶を狙いつつ、直近にも近い記憶がある状態）。
- **成立で見えるもの**：古い記憶が以前より少し想起されやすくなるが、関連と新しさのバランスで妥当な順に並ぶ（無関係な古記憶が上位を占めない）。
- **間違っていれば見えるはず**：無関係な古い記憶が上位を占め、直近の関連記憶が沈む。これが出たら、時間減衰の弱まりが効きすぎ（t 軸の半減期 `recall_half_life_days` を課題5 で締める要検討）。

### シナリオ 3：a 軸（取込 activation）が効いているか

- **狙い**：取込時の `activation_a0` が高い記憶ほど上位に出るか。ただし現状 `activation_a0` は移行時に importance から入れた値で、取込 surprise はまだ結線していない（P の後続）。よって**大きな差は期待しない**。同点近傍で a0 の高い方がわずかに上位に来れば足りる。
- **成立で見えるもの**：関連と新しさが近い2件で、`activation_a0` の高い方が上に来る。
- **間違っていれば見えるはず**：`activation_a0` を変えても順序が全く動かない（a 軸が積に効いていない）。

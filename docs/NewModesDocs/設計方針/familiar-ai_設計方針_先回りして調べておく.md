# familiar-ai 設計方針：先回りして調べておく

> 家族が気にかけていることを、聞かれる前にパジュが調べておき、結果が出たら自分から知らせる設計方針（記-ag・2026-11-25 新設）。
> 発端は、REST 内省を Letta の sleep-time（寝ているあいだの書き直し）と比べた検討である（ObsidianMemo のセッションからの申し送り）。
> 段 1（SEEKING の内なる声）、段 2（知らせる値打ちの判定と知らせ待ち）、段 3（知らせる求め）を実装した。

## 1. Letta の sleep-time と、いまの REST 内省の比較（2026-11-25）

Letta は、会話する係と、待ちの無い時間に記憶を書き直す係を分ける[^letta]。いまの REST 内省と見出しごとに比べた結果は次のとおりである。

| 見出し | Letta | いまのパジュ | 直すところ |
|---|---|---|---|
| A. 会話する係に書き換えさせない | 会話する係は記憶を読む、探すだけ。書き換えるのは書き直す係 | 同じ。主LLM の道具は思い出す道具（`recall` など）だけ。自己像と家族のいまの様子を書き直すのは REST だけ | 無い |
| B. 書き直す係に強いモデル | 書き直す係は大きく遅いモデル、会話する係は速いモデル | 書き直す REST は主LLM（Opus）。会話は調停が軽量LLM（Haiku）、答えが主LLM | 書き直しは同じ。会話に Opus を使う点は別の判断 |
| C. 書き直す頻度 | 頻度を設定で変えられる（高いほどトークンが増え、見直す時間も増える） | 誰も居ない夜に 1 回。回らない晩がある（2026-11-24 の晩） | 検討しない（2026-11-25 本人「CDは検討不要」） |
| D. 書き直しと会話を同時にするか | 同時。会話する係は、書き直しの完了を待たずに読める | 同時にしない。REST のあいだは寝ているで、声も打った言葉も捨てる（`設計方針_パジュの状態` 決定ダ） | 検討しない（2026-11-25 本人「CDは検討不要」） |
| E. 先回りして考えておく | sleep-time compute の本題。待ちの無い時間に、持っている文脈から考えを進めておく | 一部ある（音楽のおすすめ、予定表、季節を夜に用意する） | この文書で扱う |
| F. 記憶ブロックの作り | ブロックごとにラベル、説明、字数の上限を持つ | 似ている。自己像（望み、気がかり、価値）に字数の厳しい上限がある | 無い |

いまの回り方の事実（本番 DB を読むだけで数えた）：内省の記録は、2026-11-20〜25 に 1 晩 1 回、夜中から明け方（1〜6 時）に付き、11-24 の晩は無い。

[^letta]: Letta の記事 2 本（sleep-time compute・2025-04-21、agent memory・2025-07-07）。論文（arXiv:2504.13171）の本体は読んでいないので、論文の数値は確かめていない。

## 5. 実装したこと

- **段 1（2026-11-25）**：SEEKING の内なる声（`DriveConfig.voice_seeking`）を「探索したい気持ちが湧いている。家族が気にかけていて、新しい結果や情報が出るもの（試合の結果、天気など）を思い出し、それを調べる。見る・首を向けるでもよい。したくなければ何もしなくてよい。」にした（言い回しは仮）。SEEKING の発火はもとから調べもの（`search_deferred`）に決まっていて（調停の `_AFFECT_ACTIONS`）、何を調べるかの問いは軽量LLM が W（思い出した記憶を含む）から書く。SEEKING の求めはいまどおり話しかけない（出-as §2.1）。
- **段 2（2026-11-25）**：SEEKING の求めが閉じるとき（`InformationProcessing._finish` → `_keep_prefetched`）、その求めで閉じた時点までに届いた調べものの結果があれば、軽量LLM に、家族に知らせる値打ちがあるか・知らせる中身（1〜2 文）・何時間で古くなるかを聞く（`loop/prefetch.keep`）。判定には、もう知らせ待ちにあるものと知らせたもの（古くなっていないもの）も見せ、同じことは置かない。値打ちがあれば知らせ待ち（`agent_state` の `prefetched_notices`）に置く。判定は閉じるのを待たせずに裏で回し、打ち切りで消えない。軽量LLM が無いとき、呼べないとき、返りを読めないときは置かない。閉じたあとに届いた結果は使わない。
- **段 3（2026-11-25）**：T（自律機構）の輪が 30 秒に 1 回、そばに人が居て（顔ぶれか在席）、寝ていず、音楽が鳴っていず、「黙っていて」のあいだでなければ、知らせ待ちのうち古くなっていず知らせていないものを 3 件まで取り出して知らせ済みにし（`prefetch.take_due`）、`機器` の求め「調べておいたこと」を積む（`Tonic._maybe_tell_prefetched`）。話すかと言い方は主LLM が決め、在席の門はいつものまま。声になった言葉は会話の窓にも足す（聞いた人が「何対何？」と返せるように）。あいだに人が去って門に止められたら、ほかの言えなかったことと同じく「言いたかったこと」として記録に残り、差し出し直しはしない（仮）。古くなったものは知らせずに捨てる。知らせ済みも古くなるまで残し、次の判定に見せて同じことを置かない。黙っているか寝ているかを確かめられないときは知らせない。知らせ待ちを読めないときは書かない（空として上書きしない）。知らせ待ちは調べた結果の記録で、パジュの状態（耳・頭・口・体が何をしているか）ではないので、状態図には描かない。

値は `config.DriveConfig` の `prefetch_*` に置いた。

| 値 | 仮に置いたもの |
|---|---|
| 古くなるまで（返りに無いとき） | 12 時間 |
| 古くなるまでの上限 | 24 時間 |
| 知らせ待ちに置く数 | 10 件（古いほうから捨てる） |
| 判定の締切 | 60 秒 |
| 知らせ待ちを見に行く間隔 | 30 秒 |
| 1 つの求めで知らせる数 | 3 件 |

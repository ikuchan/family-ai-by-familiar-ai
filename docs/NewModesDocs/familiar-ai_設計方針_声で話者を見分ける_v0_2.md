# familiar-ai 設計方針：声で話者を見分ける（v0.2）

声は**誰が話しているか**だけを決める。在席（居るか）はカメラが決め、声は在席の証拠にしない。声の基準は、録音の手順を
作らず、名乗り（「パジュ、パパだよ」）で育てる。課題は `課題8` の知-ae。

## 1. 目的

家族が入れ替わりに話しても、話者がついてくるようにする。

話者を決める口は 3 つあった。`/speaker`、文頭の `[名前]`、名乗り（知-w）である。`/speaker` と `[名前]` はキーボードから
打つ。名乗りは、名乗ったときにしか効かない。声の照合の部品（ECAPA-TDNN・`recognition/voice.py`）はあったが、アプリの
どこからも呼ばれていなかった。書き起こしは音を文字にしたら捨てるので、照合に渡る音も無かった。顔と声の特徴は pickle
ファイルに置く作りで、開発ルール「保存は PostgreSQL のみ」に反していた。

## 2. 保存

顔と声の特徴を、PostgreSQL の 1 つの表 `recognition_embeddings` に置く（マイグレーション 073・本人の決定ア）。pickle の
保存（`EmbeddingStore`）は撤去した。ファイルは作られていなかったので、移したデータは無い。

| 列 | 中身 |
|---|---|
| `person_id` | 人（`persons` への外部キー。人を消せば特徴も消える） |
| `kind` | `face`・`voice` |
| `origin` | `registered`（登録の声・日をまたいで残る）・`today`（今日の声） |
| `day` | 今日の声の日付 |
| `vec` | 特徴（`real[]`。顔 512 次元と声 192 次元が並ぶので次元を固定しない） |

- **照らすのは人ごとの重心**：正規化した特徴の平均と比べる。1 つずつ比べて最も近いものを取ると、たまたま似た 1 つに
  引かれて取り違えが増える。
- **上限**：1 人あたり登録の声 30 発話、今日の声 10 発話（本人の決定ア・仮の値・`RECOGNITION_REGISTERED_MAX`・
  `RECOGNITION_TODAY_MAX`）。超えたら古いものから捨てる。30 発話は、名乗りが 1 日 1〜2 回なら 2〜4 週間分になる。
- **今日の声**はその日の分だけを引き、前の日までの分は照らすたびに捨てる。
- 顔の登録は人の id で受ける（`register_face(person_id, …)`）。顔をつなぐのは知-d で行う。

器は `store/recognition_embeddings.py`。

## 3. 声の特徴を運ぶ

ローカルの書き起こし（`tools/local_stt.LocalSttEngine`）が、区切りごとに、書き起こしと並べて声の特徴を取り出す
（`recognition/voice.embed_pcm`）。

- **照らす区切り**：1.5 秒以上の区切りだけ（`STT_MIN_SEGMENT_SEC`）。持ち越して単独で配った短い断片には載せない。短いと
  特徴が揺れるからだ。
- **CPU で回す**：Whisper と GPU を取り合わない。ECAPA は小さい。
- **ファイルを介さない**：16 kHz・16 bit の PCM から直に取る。
- **運び方**：特徴は書き起こしの印 `VoiceText.voice` に載り、中継（`_committed_relay`）を通っても落ちない。`agent.run` の
  先頭で読み（`voice_of`）、`push_utterance` → きっかけ（`Trigger.voice`）→ 求め（`_req.voice`）へ渡す。
- **失敗したとき**：特徴が取れなくても文字は配る。モデル（`speechbrain/spkrec-ecapa-voxceleb`）は初めて使うときに
  `~/.cache/familiar-ai/` へダウンロードし、取れなければ照合しない。

キーボードの入力と ElevenLabs の書き起こしには特徴が無い。ElevenLabs は音を外へ送る作りで、手元に音が残らない。

## 4. 話者の決まり

`push_utterance` が、門を通った声の入力で、在席があれば照らす（`_match_voice`）。窓の外で捨てた声は、聞いていないのと
同じなので照らさない。規則は純関数 `core/voice_speaker.decide` に置く。似かたは、人ごとに登録の重心と今日の重心のうち
近いほう。

| 場合 | どうするか |
|---|---|
| いまの話者に、緩い閾値（0.25・`VOICE_THRESHOLD`）以上で似ている | 続ける |
| 別の人に、厳しい閾値（0.35・`VOICE_SWITCH_THRESHOLD`）以上で、いまの話者より近い | その人へ付け替える |
| どちらでもない | 既定の人に戻す（本人の決定イ） |
| いまの話者に声の基準が無い | 続ける。厳しい閾値で別の人に当たったときだけ付け替える |
| 誰の基準も無い | 何もしない |

- **行きと帰りで閾値を変える**（本人の提案）：一度決めた話者は緩い閾値で続け、別の人への付け替えにだけ厳しい閾値を
  求める。声の揺れ（かすれ・離れて話した）では外れず、似た声（兄弟）への取り違えは起きにくい。
- **明示した話者にも同じ決まりを効かせる**：`/speaker`・`[名前]`・名乗りで決めた話者も、声が緩くその人に似ているあいだ
  だけ続く。
- **基準の無い話者を続ける理由**：「その人ではない」とは言えないからだ。`/speaker` で決めたばかりで名乗ったことの無い
  人が、次の声ですぐ外れないようにする（改造方針で承認した解釈）。
- **付け替え**は名乗りと同じ口（`_set_speaker`）で、呼びかけ名で付ける。**既定の人に戻す**ときは、PMM の話者の指定も
  外す（`clear_speaker`）。
- **今日の声に足す**：厳しい閾値以上で当たった発話の声を、今日の声に足す。登録の声には足さない。推定が日をまたいで
  残ると、取り違えが積み重なるからだ。

閾値と上限は仮の値で、家族の声を録って、本人どうしと他人どうしの似かたを測ってから見直す。

## 5. 顔との関係

顔は**誰が居るか**、声は**誰が話しているか**を決める（本人の決定イで、この設計に入れた）。

- **食い違ったら声を取る**（本人の決定ア）：声が厳しい閾値で当てた人を話者にする。映っていない人でもよい。名乗り
  （知-w）も「誰かが映っていれば効く」なので同じ扱いになる。
- **声が分からないときに顔は使わない**（本人の決定ア）：既定の人に戻す。映っている人を話者にすると、映っていない人
  （来客・テレビ）の発話が、映っている人のものとして記憶に書かれるからだ。

顔の照合はまだつながっていない。つなぐのは知-d で、そのときもこの決まりに従う。

## 6. 名乗りで基準を育てる

録音の手順は作らない（本人の決定ウ）。名乗りが話者に付いたとき、その発話の声を、その人の登録の声と今日の声に足す
（`_learn_voice`）。

- **声のもとは名乗りだけ**（本人の決定ア）：声のある発話で話者がはっきり分かるのは名乗りだけだ。`/speaker` と
  `[名前]` はキーボードで、打った人と話した人が違うことがある。
- **門を通る名乗り**：門を通るには、文頭に名前があるか（「パジュ、パパだよ」）、名前で呼んでから 30 秒の窓のうちで
  なければならない（本人の指摘）。家族への案内は「最初は『パジュ、パパだよ』と名乗ってね」になる。
- **同じ話者でも足す**：名乗りは確かな印だからだ。
- **預かった名乗り**：在席が無くて 30 秒預かった名乗り（知-w-ろ）は、声も一緒に預け、付いたときに足す。捨てたときは
  足さない。
- **足さないとき**：家族に無い名前の名乗りと、声の特徴の無い発話。

## 7. 確かめること

机上はテストで確かめた。実機では次を見る。

- **閾値**：家族どうしの似かた。特に兄弟。
- **重さ**：照合の時間と、Whisper と並べたときの遅れ。
- **登録の育ち方**：名乗りで登録が育ち、名乗らない日も話者がついてくるか。
- **雑音**：テレビの声で既定の人に戻りすぎないか。

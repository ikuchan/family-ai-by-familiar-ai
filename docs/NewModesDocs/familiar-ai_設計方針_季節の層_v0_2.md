# familiar-ai 設計方針：REST 内省・季節の層（v0.2）

季節の層は、REST 内省で**層 1（出来事を畳む）と層 2（自己像）のあいだ**に回り、**いまの季節と家のまわりの
様子**を持つ。暦・天気・まわり・家の話題の 4 つの欄を、晩に 1 回、外の検索とその晩の出来事から書き直す。
課題は `課題8` の知-ac。層の番号は振り直さず、名前で呼ぶ（層 2〜4 の番号はいまのまま）。

## 1. 目的

パジュが「もう寒いね」「金木犀が咲いたね」と、いまの季節と家のまわりを踏まえて話せるようにする。

- 日付は毎ターン渡っている（`(now …)`）。しかし**いまの様子**（寒い・セミが鳴いている・花が咲いた）は、
  日付からは出てこない。
- `ME.md` に季節を書くと、書いた瞬間から古くなる（9 月と書けば冬に嘘になる・`ME_FAMILY見直し_質問一覧` 2-11）。
  `ME.md` には変わらない住所だけを書き、いまの様子は機械が書き直す。

## 2. 外形（2026-09-26 決定）

| 項目 | 決定 |
|---|---|
| 置き場 | **DB：`agent_state` の鍵 `season_env`**。ファイルは作らない |
| 担い手 | REST 内省の**季節の層**（`loop/rest_season.py`）。層 1 の後・層 2 の前 |
| 頻度 | REST 内省の中だけ・**1 日 1 回まで** |

**`SeasonAndEnv.md` をやめて DB にした理由。** 09-20 の決定は「別ファイル `SeasonAndEnv.md` に持たせ、REST 内省で
更新する」だった。ところが機械が書き換えるファイルは、`CLAUDE.md` の開発ルール「すべての状態は PostgreSQL、
**ファイルに置くのは既定値と人の入力だけ**」に反する。本人の判断で DB に改めた（2026-09-26）。形は層 2 の自己像
（`agent_state.self_image`）と同じ。

## 3. 中身

4 つの欄。各欄 1〜2 行・1 行 40 字まで。見出しに書いた日を付ける。

```
[いまの季節とまわり]（2026-09-26 の晩に書いた）
- 暦：秋分（9/23）を過ぎたころ。次は寒露（10/8）。
- 天気：この数日は最高 24℃前後、朝晩は 15℃ほど。
- まわり：守谷では金木犀が咲き始めた。
- 家の話題：たいきの運動会が近いと話していた。
```

| 欄 | 材料 | 書き手 | 出典の検査 |
|---|---|---|---|
| 暦 | 日付 | **機械**（二十四節気の表） | 要らない |
| 天気 | 晩に 1 回の検索 | フル LLM | 検索結果から**そのまま引いた短い文**（40 字まで）を添え、本文にあるかを機械が見る |
| まわり | 同上 | フル LLM | 同上 |
| 家の話題 | 層 1 が畳んだ**その晩の出来事** | フル LLM | 出来事の id を添え、材料にあるかを機械が見る |

**暦は決まった日付の表で持つ**（本人の承認・2026-09-26）。二十四節気の日付は年によって前後 1 日ずれるが、
「〜を過ぎたころ」と書くので 1 日のずれは嘘にならない。表：小寒 1/6・大寒 1/20・立春 2/4・雨水 2/19・
啓蟄 3/6・春分 3/21・清明 4/5・穀雨 4/20・立夏 5/6・小満 5/21・芒種 6/6・夏至 6/21・小暑 7/7・大暑 7/23・
立秋 8/8・処暑 8/23・白露 9/8・秋分 9/23・寒露 10/8・霜降 10/24・立冬 11/7・小雪 11/22・大雪 12/7・冬至 12/22。

**検索の語。** `ME.md` の「住んでいるところ」から都道府県と市を取り（例：「茨城県守谷市」）、「茨城県守谷市
今週の天気 季節の話題」で 1 回引く。道具は Brave、使えなければ Tavily（調べものと同じ）。住所が取れなければ
検索しない（天気とまわりの欄は空）。

## 4. 読み手

`[いまの季節とまわり]` を、主LLM と調停のシステム文の安定部に載せる。**古さで渡し方を変える**：

| 書いてから | 渡し方 |
|---|---|
| 7 日まで | そのまま |
| 8〜30 日 | 見出しに「（N 日前の様子）」を添える |
| 31 日以上・まだ書いていない・消した | **暦の行だけ**（暦は日付から毎回計算できる） |

REST 内省は、アプリが起動していて誰も居ないときにしか回らない（9 月に 2 回）。書いた中身が古いまま
渡り続けることがあるので、日数で割り引く。

## 5. 更新（REST 内省・季節の層の仕事）

1. 今日もう書いていれば、何もしない。
2. 住所を取って検索する（取れなければ検索しない）。
3. フル LLM に、検索結果とその晩の出来事を渡し、天気・まわり・家の話題の欄を書かせる（JSON）。
4. 機械が検査する——欄・行数・字数・出典。通れば暦の行を足して保存し、`内省` の記録と計測ログ（種別
   `季節`）に残す。**通らなければ前の値を残す**。

まとめ方は LLM、通すかどうかは機械（層 1・層 2 と同じ分担）。

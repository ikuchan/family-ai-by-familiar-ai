## 目的

想起スコアの改造は全体テストで回帰を防げるが、**想起順が体感として破綻しないか**は実データと実会話でしか見えない。本書は、各 P スライスの挙動変化を実機で確かめる手順と、**成り立つ場合に見えるもの／間違っていれば見えるはず**を対で記す。判定は「事実（画面・ログで見えたこと）」だけで下す。

対象アプリの起動は `./run-gui.sh`。会話入力は `recall_async(user_input, recall_mode="conversation")` に流れ、その結果がフルLLM の文脈へ載る。よって「記憶を問う対話」を打ち、返答に現れる記憶と、想起ログ（`recall` の score 順）を見る。

**実施タイミング**：各 P スライスを打つたびに毎回は回さない。チャットレベルの改修（P スライス群）が一通り終わり、知覚（DIF・在席検出・話者帰属）を作る前の段階で、たまった P-1〜P-4 の挙動をまとめて実機で確認する。それまでは各スライスの全体テスト緑で回帰を担保し、本書に判定を溜める。

## 共通の前提と観測点

- **起動**：`./run-gui.sh`（`uv run familiar --gui`）。普段の運用がこれなので、実機確認も同じ口から行う。`./run.sh` は `--gui` を付けない CLI 起動で、`run_gui` が呼ばれず GUI のアイドルループ（`gui.py` の `_process_queue()`）が回らない（`main.py:459,500`）。自発ターンや遅延配信が絡む確認は CLI では見えないので、想起だけを見る場合でも運用と同じ GUI で行う。実データ（本番 DB の記憶）で行う。空の DB では想起の差が出ないため、日付にばらつきのある観測が数十件以上ある状態で行う。
- **観測点**：(a) 返答に現れる記憶の内容、(b) 想起ログの score 順（`recall` の返り値の `score`）、(c) 想起された記憶の日付。**`recall` は現在スコアをログへ出していない**（`memory.py` に該当ログなし）ので、実施時に `recall` の返り値を出す一時的な debug ログを足す（score・日付・a0・n、スライス3 以降は観測 PAD と現在 mood も）。確認が済んだら外す。
- **記録**：各シナリオで「見えたもの」を下の記録表に書き、成立／破綻を判定する。

## P-1：活性の想起接続・時間減衰の t 軸一元化

### 変えたこと（事実）

`_compute_final_score` の積を `importance` から `_derive_activation(activation_a0, activation_n)` へ替えた。あわせて `importance` の日次減衰（`_generate_day_summary` の `decay_importance`）を撤去し、時間減衰は `time_score`（t 軸）だけにした。n は当面 0 のため、a 軸は取込値 `activation_a0` の錨で効く。

### シナリオ 1：時間減衰が t 軸で生きているか

- **操作**：新しい話題と、明確に古い話題（数週間前の記憶に触れる問い）を続けて問う。例：「昨日の話をして」「先月の◯◯の話は？」
- **成立で見えるもの**：新しい記憶が古い記憶より上位に来る（score が高い）。古い記憶も沈みはするが完全には消えない（floor で下げ止まる）。
- **間違っていれば見えるはず**：古い記憶が新しい記憶より上位に来る／新しい記憶が想起されない。これが出たら t 軸（time_score）の結線が壊れている。

### シナリオ 2：二重減衰の撤去で古い記憶が沈みにくくなっていないか

- **狙い**：importance の日次 0.95 減衰を外したので、**以前より古い記憶がやや上がる**はず（時間減衰が二重から一重へ）。過度に上がって新しい記憶を押しのけないかを見る。
- **操作**：関連の強い古い記憶と、関連の弱い新しい記憶が競合する問いを打つ（話題語で古い記憶を狙いつつ、直近にも近い記憶がある状態）。
- **成立で見えるもの**：古い記憶が以前より少し想起されやすくなるが、関連と新しさのバランスで妥当な順に並ぶ（無関係な古記憶が上位を占めない）。
- **間違っていれば見えるはず**：無関係な古い記憶が上位を占め、直近の関連記憶が沈む。これが出たら、時間減衰の弱まりが効きすぎ（t 軸の半減期 `recall_half_life_days` を課題5 で締める要検討）。

### シナリオ 3：a 軸（取込 activation）が効いているか

- **狙い**：取込時の `activation_a0` が高い記憶ほど上位に出るか。ただし現状 `activation_a0` は移行時に importance から入れた値で、取込 surprise はまだ結線していない（P の後続）。よって**大きな差は期待しない**。同点近傍で a0 の高い方がわずかに上位に来れば足りる。
- **成立で見えるもの**：関連と新しさが近い2件で、`activation_a0` の高い方が上に来る。
- **間違っていれば見えるはず**：`activation_a0` を変えても順序が全く動かない（a 軸が積に効いていない）。

## P-3：書き込み PAD 化（W2b-2・評価器の PAD 出力）

### 変えたこと（事実）

観測の感情を、評価器（軽量LLM）が P/Pn/Dom で直接出すようにした。A 軸は機械 arousal。値踏みゲート A_gate=0.25（arousal 未満は評価器を呼ばず P/Pn/Dom＝現在 mood）。旧 `_infer_emotion`（ラベル直出し）を撤去し、消費者向けラベルは PAD から派生（`label_from_pad`）。会話記憶（会話 summary）と生観測に PAD 列（emotion_p/pn/a/dom）が入る。

この段は書き込み side で、想起順への効きは e 軸（スライス3）が入って初めて見える。ここで見るのは「PAD が妥当に書かれるか」と「静かなターンで評価器が動かないか」まで。

### シナリオ 1：感情のある遣り取りで PAD が書かれるか

- **操作**：はっきり感情の乗る遣り取り（喜び・悲しみ）を1往復し、その会話記憶の PAD 列を DB で見る（`SELECT emotion_p,emotion_pn,emotion_a,emotion_dom FROM observations WHERE kind='conversation' ORDER BY timestamp DESC LIMIT 1`）。
- **成立で見えるもの**：喜びは P 高・Pn 低、悲しみは P 低・Pn 高。A は arousal 相応。既定0.5のままでない。
- **間違っていれば見えるはず**：PAD が全軸0.5のまま（評価器が繋がっていない／payload に載っていない）、または解析失敗で常に mood になる。

### シナリオ 2：静かなターンで評価器 LLM が動かないか（A_gate）

- **操作**：淡々とした短い相槌（「うん」「そうだね」）のターンを打ち、utility バックエンドの呼び出しログを見る。
- **成立で見えるもの**：arousal<0.25 のターンで評価器 complete が呼ばれず、会話記憶の P/Pn/Dom が現在 mood（移行期は中立0.5）と一致する。
- **間違っていれば見えるはず**：静かなターンでも毎回評価器が呼ばれる（A_gate が効いていない）。

## スライス3：e 軸のスコア接続（ハイブリッド合成）

### 変えたこと（事実）

想起スコアの合成を純積から `score = r^{w_r} × (w_t·t + w_e·e + w_a·a)/(w_t+w_e+w_a)` へ替えた。基底は $(1,1,1,1.5)$。e＝**今の気分と観測 PAD の距離**（記憶どうしの距離ではない）で、mood は想起1回につき1つ読み全候補に共通に使う。r はコサインを $c_{lo}{=}0$／$c_{hi}{=}1$ で伸長した値（現行値では恒等）。あわせて既定値を課題5 v0.24 へ揃えた（半減期 7日→3日、$t_{floor}$ 0.25→0.001）。p 軸は知覚待ちで項ごと持たない。

挙動変化は3つある。気分に近い感情の記憶が上位へ寄ること、一軸が低いだけでは記憶が沈まなくなること（純積では消えていた）、半減期短縮で新しさの効きが強まることである。

### シナリオ 1：気分一致想起が効いているか

- **操作**：感情の乗る遣り取りを何度か重ねて mood を一方へ振り（`agent_state` の `mood_pad` を DB で確認）、そのうえで感情の異なる記憶がどちらも引っかかる問いを打つ。想起ログの score 順を見る。次に反対向きの遣り取りで mood を逆へ振り、**同じ問い**を打つ。
- **成立で見えるもの**：同じ問いに対して、mood を振った向きに合う感情の記憶が上位へ来る。mood を逆へ振ると順位が入れ替わる。
- **間違っていれば見えるはず**：mood をどちらへ振っても順位が変わらない（e が効いていない・mood が読めず None で項が外れている）。あるいは mood と無関係に、感情の強い記憶だけが常に上位に来る（距離でなく強度で効いている）。

### シナリオ 2：e が拒否権になっていないか

- **操作**：いまの気分から遠い感情を持つが、関連が強く activation も高い記憶があるはずの問いを打つ。
- **成立で見えるもの**：その記憶が想起に残る（順位は下がりうるが消えない）。
- **間違っていれば見えるはず**：感情が遠いだけで候補から消える。これは加算部でなく乗算で e を足したときの症状で、設計と逆である。

### シナリオ 3：半減期短縮で古い記憶が沈みすぎていないか

- **操作**：UC⑥ の「古い話」の型（数週間前の出来事を問う）を打つ。
- **成立で見えるもの**：古い記憶が $min\_score$ を割らずに残る。t が下がっても $a$ と $e$ が補償する。
- **間違っていれば見えるはず**：3日以上前の記憶がまとめて出てこなくなる。その場合は半減期でなく $w_a$ か $min\_score$ の調整で見る（$HL$ は課題5 の確定値）。

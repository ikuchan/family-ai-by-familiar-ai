# チケット：埋め込みモデル移行 multilingual-e5-small → bge-m3（現行システム）（v0.3）

## 前提条件（着手前に満たすこと）
 
- **BUG-1 の完了**：A（`save_async_with_id` の時間窓冪等化）＋B（既存重複の purge マイグレーション）が両方マージ・適用済みであること。重複が残ったまま再埋め込みすると bge-m3 でも重複ベクトルが焼き直されるため。BUG-1 完了後の**クリーンなデータ**に対して本移行を実施する。
## メタ
 
- 分類：保守（埋め込み基盤の差し替え・DB マイグレーション）
- 重要度：中（recall 品質の改善・後続の c_lo/c_hi 確定の前提）
- 対象：現行システム（新設計の実装ではない）
- 関連：課題7（計測）・根拠台帳 §6／§3・BUG-1（重複・順序に注意）・計測指示書 v0.5（再測定）
## 目的
 
- 埋め込みを bge-m3（1024次元）へ差し替え、全観測を再埋め込みする。
- 平均中心化 `mu` を bge-m3 ベクトルで再計算する。
- 移行後に c_lo/c_hi・min_score を再測定できる状態にする（再測定自体は計測指示書 v0.5）。
## 影響範囲（コードで確認済み）
 
### コード（`src/familiar_agent/tools/memory.py`）
- `EMBEDDING_MODEL = "intfloat/multilingual-e5-small"`（:40）→ **`"BAAI/bge-m3"`**。
- `EMBEDDING_DIM = 384`（:41）→ **`1024`**。
- **e5 プレフィックスの除去（必須）**：`passage: {t}`（:293）・`query: {t}`（:309）は e5 の規約。**bge-m3 はプレフィックス無しで素のテキストを encode する**。付けたままだと品質が落ちるため、bge-m3 では付与しない（プレフィックスを条件分岐で外す／空にする）。
- モデルロードは `SentenceTransformer(model_name)`（:259 付近）で bge-m3 も読める（dense 1024次元・cosine 用に正規化）。`_pad_or_truncate`（EMBEDDING_DIM 依存）・失敗時フォールバック（`[0.0]*EMBEDDING_DIM`）は新次元で整合。
### DB
- **situated_embeddings.vector**：`vector(384)`（migration 011:16）→ **`vector(1024)`**。HNSW 索引 `USING hnsw (vector vector_cosine_ops)`（011:27）は**削除→再作成**が要る（次元変更のため）。
- **obs_embeddings.vector は BYTEA**（migration 001）＝**スキーマ変更不要**。コードの再エンコードで内容だけ入れ替わる。
### 前処理
- **平均中心化 `mu` の再計算**：課題7 の `mu_final_*.npy` は e5-small/384次元のもので **bge-m3 では無効**。再埋め込み後に bge-m3 ベクトルで `mu` を再計算し直す。
## 移行手順
 
1. **前提確認**：BUG-1（A 冪等化＋B purge）が適用済みで、確認 SQL（`GROUP BY vector HAVING COUNT(*)>1`）で完全重複が0件であることを確認。0件でなければ着手しない。
2. **バックアップ**：observations／situated_embeddings／obs_embeddings をダンプ（ロールバック用）。
3. **コード差し替え**：`EMBEDDING_MODEL`／`EMBEDDING_DIM` を bge-m3／1024 に、e5 プレフィックスを bge-m3 では付けないように変更。
4. **スキーマ変更**：situated_embeddings の HNSW 索引を drop → `vector` 列を `vector(1024)` へ（既存データは再埋め込みで入れ替わるので、列再作成 or 一旦空にして再投入）。
5. **全再埋め込み**：全 observations（計測時点 2,618件）の obs_embeddings を bge-m3 で再生成。situated_embeddings は登録 person＋自分ぶん（計測時点 10,472件）を再生成。既存の materialize ワーカー経路を使うか、専用バッチで実施。
6. **HNSW 索引再作成**：`vector(1024)` に対し `vector_cosine_ops` で再構築。
7. **mu 再計算**：bge-m3 ベクトルで person_id 別の平均ベクトルを再算出し保存（平均中心化に使用）。
8. **再測定**：計測指示書 v0.5 の計測1（中心化後・時間ギャップ擬似セッション）を bge-m3 で実施し、c_lo/c_hi の窓と意味分離が改善したか確認。
## 完了条件
 
- コード：`grep` で `multilingual-e5-small`／`e5-small`／`EMBEDDING_DIM = 384` の現役参照が**0件**（履歴コメントを除く）。`passage:`／`query:` プレフィックスが bge-m3 経路に**残っていない**こと。
- DB：situated_embeddings の全ベクトルが **1024次元**（`vector_dims(vector)=1024` が全行）。`vector(384)` 列定義の残存ゼロ。HNSW 索引が 1024次元で再作成済み。
- 再埋め込み件数が観測件数と整合（obs_embeddings＝observations 件数・孤児ゼロ）。
- 数えた件数は網羅の証明にしない。「旧次元・旧モデル名で検索して0件」「全行 1024次元」を完了の証明とする。
- 平均中心化 `mu` が bge-m3 ベクトルで再計算され保存されている。
## テスト
 
- 単体：encode が 1024次元を返す／bge-m3 でプレフィックスが付かない／`_pad_or_truncate` が 1024 で no-op。
- recall：再埋め込み後に既知クエリで妥当な近傍が返る（次元不整合エラーが出ない）。
- マイグレーション：小規模フィクスチャで 384→1024 列変更・再埋め込み・索引再作成が通り、旧次元残存ゼロ。
- 既存テストの修正：エンコーダをモックして小ベクトルを返すテスト（`_pad_or_truncate` 前提）が 1024 でも通るか確認。`EMBEDDING_DIM`／384 をハードコードしたテストの洗い出し（`grep 384`）。
- DB 更新を伴うため、マイグレーション手順をテストに含める。全体テストは `./scripts/run_tests.sh` で自分（Claude Code）が回す。
## リスク・ロールバック
 
- bge-m3 は系列・プレフィックス規約が e5 と異なるため、**プレフィックス除去漏れ**が最大の品質リスク（要レビュー）。
- 次元不整合（DB 1024・コード 384 などの取り違え）で recall が全滅しうる。コードと DB の次元を**同時に**合わせる。
- ロールバック＝バックアップから observations／embeddings を復元し、コードを e5-small/384 に戻す。移行は「新列で並行構築→切替」にすると無停止に近づけられる（任意）。
- VRAM：bge-m3 は GPU 1.5〜2.2GB 想定で 3060 に余裕（計測5）。再埋め込みのバッチ実行時間は1万件規模で数分オーダー。
## 残確認（実施前）
 
- 再埋め込みの実行経路：既存 materialize ワーカーで全件再生成できるか、専用バッチが要るか。
- bge-m3 の利用形態：dense（1024次元コサイン）のみで足りる前提（sparse/ColBERT は使わない）。

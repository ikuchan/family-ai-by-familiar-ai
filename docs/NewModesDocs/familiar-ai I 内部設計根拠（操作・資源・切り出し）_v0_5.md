# familiar-ai I 内部設計根拠（操作・資源・切り出し）（v0.5）

## 位置づけ
[D-I内部] の根拠メモ。**境界・コンポーネント・図は設計図 [D-I内部]／③ が正**。本書はそこに載せない**設計根拠**（内部ループ手順・MI 操作の持ち主・コンポーネント別資源プロファイル・切り出しの理由）だけを残す。用語は用語一覧「I 内部再設計（[D-I内部]）」セクションを参照。
 
## 3. 内部ループ（パターンB・イベント駆動・1反復）
ループ核は **3キュー（AIFキュー＝情動／DIFキュー＝機器／完了キュー＝LLM・MCP結果）の union を待ち、来たどれでも起きる**（時計は見ない）。**W は store でなく毎反復 O から構築する派生ビュー**（[D-記憶単一化]）。
 
1. **取り込み**：3キューを drain し、来た事実（情動・機器イベント・完了結果）を **O に書く**（[D-O書込]）。完了結果も O に書くだけで、**相関ID も W の pending も使わない**（[D-単一想起]）。
2. **W 構築（想起）**：O（＋現入力）から **recall_score＝関連ゲート(`cosine` の r^(w_r))×（新しさ `time_score`・感情・`根づき`・在席者相関 の加重平均）（ハイブリッド・[D-想起合成]／[D-在席相関]）** で W を組む。**自己認識 MI は pinned で常時含む**。在席者がいる間は在席者相関 p（在席他者との situated 結びつき・自分除外・noisy-OR）も候補集合と score に効く（在席者ゼロなら p を外す）。完了は **関連＋未解決で O の起点（open 意図）に再会**。情動は中身を持たないので新しさ＋感情一致＋自己認識 MI が主、drive は調停が drive-serving に使う。
3. **評価**：驚き・感情・予測・値踏み・意味づけ（驚き＝現在の見え DIF vs 自分の期待）。**drive/mood は PI の `drive`/`emotion` として受け、norm/presence（T(G) private）は読まない**（[D-B分離]）。
4. **調停（軽量LLM）**：候補を機械で点数づけ（**drive-serving**＝D→調停で重みづけ・`根づき`・継続ボーナス）し、**軽量LLM が候補から1つ選ぶ**（構造化・非対話・[D-反復出力]）。出力は常に**1つの work（の第1動作）**。会話応答では、軽量LLM が**重さを自己判断**して3分岐に振り分ける（基準は作り込まず軽量LLM の自己判断・調整はプロンプト）：**(a) 軽量で閉じる**＝短文で答えきれる会話は軽量LLM が応答して反復を閉じる（フルを起こさない・「会話は必ずフル」ではない）／**(b) 軽量つなぎ→フル**＝熟慮・想起が要る会話は段5へ／**(c) 定型**＝定型動作・応答不要は軽量＋動作器で閉じる。誤判定が問題化したら想起結果（段2）を手がかりに足す余地（今は入れない）。
5. **生成／動作**：**フルLLM（生成器）は言語生成・複雑な行動の組み立てのときだけ同期で起こす**。**定型動作（見る・移動・再生・候補選択）は軽量LLM の調停＋動作器でフルLLM を起こさず閉じる**（[D-反復出力]）。**フルで答えると決めたとき（段4の b）は、同じ同期フロー内で二段生成する**：まず軽量LLM が**つなぎ・受けを即答**（相槌・「えっと」等の前置き発話・**内容にコミットしない**＝本応答との食い違い回避）し、続けて同期でフルLLM を起こして本応答を生成・発話する。これは**1つの work の内部二段**で、反復をまたがず別出力でもない（**1反復＝1出力・フル同期**を保つ・軽量即答はフル生成の体感レイテンシを埋める前置き）。動作要求は DIF（機器）／実行担当（MCP）へ。**配信ゲート（結果有り＋在席）**を通った分だけ出す。**1反復＝1出力**で、続きは結果（観察＝機器イベント／完了）が次反復を起こす。**待たない（投げっぱなし）のは deferred 外部呼び出し（検索/取得）だけ**で、その結果が完了キュー→O 経由で次反復の入力になる。
6. **処理結果を O に書く**：want と result を突き合わせ、充足／不足／失敗で **O の status を更新**（`根づき` を落とす＝解決。**supersede は使わない＝版履歴専用**）。同居が再検索を防ぐ。
7. **送出**：必要なら Nudge を AIF キューへ（Nudge の PI/MI 化は未決）。
8. **W 破棄**：W は派生なので反復末に捨てる。**eviction／退避／失効 store は無い**（新しさ＝time_score が時刻で薄れ、`根づき` はイベント駆動・統合は REST 内省の別リズム）。
重い処理のうち **deferred 外部呼び出し（検索/取得）だけ投げっぱなしで非同期**（**フルLLM 生成は同期**・[D-反復出力]）、安価操作は**ループ内同期**。タイマーは **T が due で情動を発火**（I は時計を持たない・課題9）。
 
## 4. MI 操作 → 持ち主
| 操作 | 持ち主 |
|---|---|
| 受け取る（外部→MI） | AIF／DIF／完了（3キュー）→ メイン取り込み |
| W 構築（想起 O→W・毎反復） | メイン |
| 活性を算出（on-read） | 読む各機構（C の τ） |
| 評価（驚き・感情・予測・値踏み・意味づけ） | 評価器 |
| 生成（指示構築＋LLM＋解釈） | 生成器 |
| 選ぶ・調停（drive-serving 選択・**軽量LLM**） | メイン内 調停器 |
| 動作発生 | 動作器（→DIF／実行担当） |
| 送出（Nudge → T） | メイン → AIF |
| 解釈（文字→MI） | 生成器 |
| 保存（O append）／更新（supersede・消費・status）／活性減衰（on-read） | 実行者が O 書込＋統合保守器 |
| 統合（consolidate・REST 内省） | 統合保守器 |
 
## 5. コンポーネント別 資源プロファイル
| コンポーネント | 外部（DIF） | フルLLM | 軽量LLM | GPU | I 外（T） |
|---|---|---|---|---|---|
| 生成器 | － | ✓ | － | － | － |
| 評価器 | △（カメラ） | － | ✓ | △（見え／識別） | － |
| 動作器 | ✓（機器） | － | － | △（TTS／識別） | － |
| 統合保守器 | － | △ | － | ✓（near-dup） | － |

外部接続は **DIF だけ**（LLM・MCP は内部）。**I 外接続は メイン↔T（情動受信・Nudge 送出）のみ**。**T レジスタには繋がらない**（drive／mood は **PI の `drive`/`emotion`** として受け）、**norm／presence（T(G) private）は読まない**。評価の驚きは現在の見え vs 自分の期待で出す（T の per-pose-norm を引かない・[D-B分離]）。
 
## 6. 切り出しの根拠
| 切り出し | 理由 |
|---|---|
| 生成器 | フルLLM を1か所に封じ込め・**言語生成/複雑判断のときだけ同期で起こす** |
| 評価器 | 軽量LLM＋GPU の「理解を作る」専用処理 |
| 動作器 | 機器・ツール結合を隔離する出力アダプタ |
| 統合保守器 | ループと**別リズム**（定期・アイドル時）で GPU/LLM を使う |
| 調停器＝メイン内（**軽量LLM**） | 「次に何をするか」の候補選択（構造化・非対話）はループ管理の本務 |
| 想起＝関数 | 薄い読み（独立化不要） |

## 実装で判明した事実（段階1〜2・2026-07-25）

設計そのものは変えないが、実装して初めて分かった前提を記録する。詳細は `イベント駆動ループ`（v0.19）。

- **取り込みで書いた記録が、そのままでは自分の想起を汚す**。手順1で O に書き、手順2で O から W を組むので、**記録は検索より前に存在する**。トリガ O は人の問いと同一文なのでコサインが最大に近く、open 意図 O は探す語を丸ごと含むため、その語で探せば必ず上位に来る。supersede は検索の後にしか効かないので前倒しでは間に合わない（実測でも完了から supersede まで 48ms、その間に検索は走らない）。**取り込みで書いた記録（＝ループ記録の鎖の先頭）を、検索からは外し、W へは決定的に加える**ことで解いた。この規則は3キューのどれにも同じ形で当てはまる。
- **ループ記録は1本の鎖にすると管理が閉じる**。トリガ O → open 意図 O → 完了 O と、新しい記録が直前の生きた記録を supersede する。生き残るのは常に先頭1件だけになり、「未解決の意図が溜まる」「前の記録が想起に出る」が構造的に起きない。
- **1反復の出力にはツール投げも含まれる**。手順5 の「1反復＝1出力」を「発話を1つ出す」と読むと、ツールを投げた反復の終端処理（supersede・W 破棄）が抜け落ちる。**ツールを投げた時点でその反復は終わり**、続きは完了キュー到来で起きる。
- **段4 の3分岐は所要時間に直結する**。フルLLM を毎反復呼ぶと1ターン 10.5 秒（うち LLM 10.2 秒）だったものが、調停で light/action を軽量LLM に閉じさせて 4.2 秒になった（計測台帳 §15）。

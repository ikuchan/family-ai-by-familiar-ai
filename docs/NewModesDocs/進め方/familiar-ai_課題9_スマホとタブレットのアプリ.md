# familiar-ai 課題9：スマホとタブレットのアプリ

> スマホとタブレットのアプリを作り、パジュの外の入口（外部の口）にする大きな課題の、課題の正本。
> 課題8 とは別に、この課題の段と未決をここで持つ（2026-11-24 新設・本人の指示「新しい課題管理ページを作りなさい」）。
> 課題8 §7 の表には、この文書を指す 1 行だけを置く。

## 1. 本人の言葉と狙い

2026-11-24 の本人の言葉：

- 「新しい大きな課題として、スマホ及びタブレットのアプリをつくります。パジュの外部インターフェースにします。」
- 「顔認識等ができないし、通信負荷をあまりかけたくないので、音声による人の識別は不要で、かわりに、誰が話してるかボタンを
  押してその情報を渡せるようにしていくことを大まかには考えています。」

ここから読める狙いは次の 3 つである（本人の言葉そのものではない。§3 の問いで確かめる）。

| 狙い | 中身 |
|---|---|
| 入口を増やす | パジュの機体（家の Linux 機）の前に居なくても、スマホやタブレットからパジュと話せる |
| 話者はボタンで渡す | アプリでは顔も声紋も使わない。話す人がボタンで自分を選び、その名前を言葉と一緒にパジュへ渡す |
| 通信を軽くする | アプリとパジュのあいだで送るものを少なくする（声の識別のための音を送らない） |

## 2. いまのパジュで分かっていること（2026-11-24・コードを読んだ事実）

| 事実 | 根拠 |
|---|---|
| パジュには、外から話しかけられる口（家のネットワークで待ち受ける口）が無い。入口は機体の画面（GUI）と端末の画面とマイクだけ | `src/familiar_agent` に待ち受ける口が無い（通信の部品は、外へ出ていく呼び出しにだけ使っている） |
| 話者をはっきり指定する口が、すでに 2 つある。画面の命令 `/speaker 〈名前〉` と、打った言葉の頭の `[名前]` | `agent.py`（`/speaker`）、`relationship.py`（明示された話者） |
| 明示された話者は、声紋で見分けた話者より強い（はっきり指定した話者の持ち時間 60 秒のあいだは、窓の外の声で付け替えない） | `event_loop._listen_swallowed_voice`（知-as 段 2） |
| 声の書き起こしは、機体のマイクの音を機体の中で書き起こす | `tools/stt.py`、`local_stt` |
| パジュの声は、機体が Gemini の声の合成（外のサービス・`gemini-3.8-flash-lite-tts`、声の種類 `ja-jp-commercial-3`）に頼んで作り、機体につないだスピーカー（YAMAHA）から出す。機体の中で作る Style-Bert-VITS2 も入っているが、いまは使っていない | `config.TTSConfig`（`engine` の既定 `gemini`）、起動のログ「声の担い手」、`tools/tts.py`、`io/dif.py` |
| パジュを動かすのは家の Linux 機だけで、ほかの機械へは配らない | 2026-11-23 本人の決定 |

アプリのボタンは、いまの `/speaker 〈名前〉` と同じ働き（話者をはっきり指定する）にできる見込みが高い〔推測〕。

名前を呼ぶ合図をスマホで聞くので、アプリから届いた言葉は、パジュの側では「名前を呼んで話しかけられた言葉」として扱うことになる見込みである〔推測・端-b の設計で確かめる〕。いまの機体では、名前の聞き取りと、名前で開く窓（`WakeWindow`）は機体の中にある。

## 3. 決めること（本人に一つずつ聞く・上流から）

上の問いの答えで、下の問いが変わる。答えが出たら「決めたこと」へ移す。

| 順 | 問い | なぜ先に要るか |
|---|---|---|
| 1 | アプリで何をするか：パジュと**声**で話すのか、**字**で話すのか、両方か | 送るもの（音か字か）と、書き起こしをどこでするかが決まる |
| 2 | どこから使うか：家の中だけか、外出先からもか | 家のネットワークの中だけで済むか、外から入れる道（と、その守り）が要るかが決まる |
| 3 | パジュの返事をどこで出すか：アプリ（スマホの画面と音）か、家のスピーカーか、両方か | 返事の声をアプリへ送るか、字だけ送るかが決まる |
| 4 | 書き起こしをどこでするか：スマホ（端末の音声認識）か、パジュの機体か | 1 で声を選んだときだけ。通信の量とプライバシーが変わる |
| 5 | 話者のボタン：誰を並べるか（FAMILY.md の家族の全員か）、一度押せば続くか毎回押すか、子どもも使うか | 話者の持ち時間と、押し忘れたときの扱いが決まる |
| 6 | 誰が入れるか：アプリを使える人の決め方（家族の端末だけにする鍵） | 外の口を開けるので、家族以外が話しかけられないようにする |
| 7 | 作り方：スマホとタブレットの種類（iPhone か Android か、両方か）と、アプリの形（端末に入れるアプリか、ブラウザで開くページか） | 作る道具と配り方が決まる |

## 4. 決めたこと

| 問い | 決めたこと | 日付 |
|---|---|---|
| 1 | アプリでは、声と字の両方でパジュと話す。ふだんは声で話し、声を出しにくい場面では字も打てる。話者のボタンはどちらでも同じに使う | 2026-11-24 本人 |
| 2 | 家の中だけでなく、外出先からも使う。外から入れる道と、家族以外を入れない守り（問い 6）が要る | 2026-11-24 本人 |
| 3 | アプリから話しかけたときの返事は、話しかけた端末にだけ返す（字と声）。家のスピーカーは鳴らさない | 2026-11-24 本人 |
| 3 の続き | 返事の声は、スマホが Gemini（いまパジュの声を作っている外の声の合成）に直接頼む。機体は返事の字と、声の設定（合成のモデルと声の種類）だけを送る。鍵は機体とは別のアプリ用を作り、使える量の上限と、そのアプリからだけ使える制限を付ける（制限は送り元の申告を見るので、完全な守りではない）。短い期限の鍵を機体が配れるかは、作る段で調べる（本人「スマホがgeminiに頼めばよくないですか？」） | 2026-11-24 本人 |
| 4 | 声の書き起こしはスマホでする。パジュの名前を呼ぶ合図（「パジュ」と呼ばれたかの聞き取り）も、スマホの中で聞く。パジュへ送るのは字と話者だけ（本人「スマホで、パジュのウェイクワード対応自体をローカルでいれる方向」） | 2026-11-24 本人 |
| 5 | 話者のボタンは、押すまでその人のまま。端末ごとにいまの話者が 1 人決まっていて、代わるときだけボタンで切り替える。ボタンに並べるのは FAMILY.md の家族の全員〔仮（本人の確認待ち）〕 | 2026-11-24 本人 |
| 6 | 外出先からは、家族の端末だけがつながる私用の通り道（Tailscale）で入る。家のルーターに穴を開けず、家族の端末以外は届かない。行き先に、Tailscale が止められているという報告のある国（中国、イラン、ロシア、トルコ、ミャンマー。第三者の報告で、公式の発表は無い）は入らない。機体に Tailscale を入れるときは、別に承認を取る（依存の追加） | 2026-11-24 本人 |
| 7 | 家族の端末は Android だけ。アプリは端末に入れるアプリにする（名前を呼ぶ合図と書き起こしを端末の中でするので、ブラウザで開くページでは聞き続けにくい・問い 4 からの帰結）。配り方は、家族の端末へ直接入れる（ストアに出さない）〔仮（本人の確認待ち）〕 | 2026-11-25 本人 |

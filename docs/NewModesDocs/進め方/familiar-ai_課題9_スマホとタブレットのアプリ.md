## 6. 端-b の設計方針（機体の外の口・2026-11-25 から本人と決めている）

### 6.1 いまの入口と出口（コードを読んだ事実）

| 事実 | 根拠 |
|---|---|
| 人の言葉は、声も打った言葉も、同じ入口（`push_utterance`）から 1 つの待ち行列に並ぶ。求めは同時に 1 つで、順に答える | `loop/event_loop.push_utterance`、`_take_trigger` |
| 打った言葉（入口の種類 `keyboard`）は、名前を呼ばれた言葉と同じに扱う（名前の窓を見ない） | `event_loop`（`named=… or source == "keyboard"`） |
| 返事は、家のスピーカーで声にし（`_say_aloud`）、画面へも出す（`_emit`）。打った言葉への返事も、家で声になる | `event_loop._speak`、`_emit` |
| 考えているあいだは、家のスピーカーで待ちの電子音と合図を鳴らす | `event_loop._beep_while_waiting`、`io/dif.play_cue` |
| 外の口を作る部品（待ち受けの `aiohttp.web`）は、いまの依存の `aiohttp` に入っている。依存は増えない | `pyproject.toml` |

### 6.2 原因と対応案

アプリから届いた言葉は、いまの入口にそのまま流すと、返事が家のスピーカーで声になり、電子音も家で鳴る。いまの作りには「この求めの返事をどこへ返すか」が無く、返事の出口がいつも家だからである。

対応案は、求めに**返事の行き先**（家か、どの端末か）を持たせ、アプリから届いた言葉の求めでは、返事の字を話しかけた端末へ返し、家の声と電子音を出さないことである。入口は、いまの打った言葉と同じ道（名前を呼ばれた言葉・話者を明示した言葉）を通す。

### 6.5 段 1-ろ の分け方と、できたこと

段 1-ろ は、外から届く口（待ち受け）を最後に作る。中の決まりが揃うまで、外から話しかけられないようにするためである。

| 段 | 中身 | 状態 |
|---|---|---|
| 1-ろ-1 | **窓の持ち主**と、別の口の言葉を断る門 | 済み（2026-11-25） |
| 1-ろ-2 | **返事の行き先**：端末の求めの返事を、家で声にせず端末へ返す。家の電子音と合図も鳴らさない | 済み（2026-11-25） |
| 1-ろ-3 | **話者**：端末で選んだ話者を、家のそばに居る人に数えずに、その求めの話者にする（b3） | 未着手 |
| 1-ろ-4 | **待ち受けの口**：端末の字と話者を受け、返事を送る口 | 未着手 |

1-ろ-1 でできたことは次のとおりである。

- 窓のデータに持ち主（家は空、端末はその端末の名前・`WakeWindow.owner`）を持たせた。閉じた窓を開けた口が持ち主になり、開いているあいだは変わらない。ほかの口は開け直しも延ばしもできない。
- 門の最初（`_mouth_gate`）で、窓が開いていて持ち主が別の口なら、その口の言葉を名前があっても断る。家の言葉は、ログに残して捨てる（家の話し中の音は段 1-は）。
- 端末の言葉は、端末の中で名前の合図を聞いてあるので、名前で呼ばれた言葉として受け、窓をその端末のものとして開ける。耳の入口と家の「黙って」は見ない（b4）。黙るのは解かず、黙っていたあいだに控えた家の言葉も、端末の求めへ渡さない。
- 口の違う言葉は、調べもの中の求めに添えず、考え直しにも見せず、その求めが閉じるまで待たせる。待たせた言葉を取り出すとき、窓がいま別の口のものなら断る。端末の求めでは、家で聞いた確認（タイマーを掛ける前など）の答えを読まない。
- 窓を保つのは、窓の持ち主の求めだけにした（頭のデータに求めの口を持たせた）。端末の窓のあいだに家の情動の求めが考えていても、端末の窓を保たない。家の求めは、端末の窓の会話を読まない。持ち主の変わる窓は、新しい窓の会話にする。
- 端末の求めは、家の「黙って」を調停に伝えず、掛けも解きもしない（b4）。
- 言葉を列から取り出すときにも、窓がいま別の口のものなら断る（門の中で Jev を待つあいだや、列で待つあいだに、別の口が窓を取ることがある）。窓の持ち主は、持ち主が窓を開けた時刻より前に話し始めた言葉には居なかったものとして見る。
- 窓の持ち主と求めの口は、状態ではなく窓と頭のデータ（閉じる時刻と同じ扱い）なので、状態図の領域と移りは増やしていない。
- 端末から言葉が届く口は 1-ろ-4 で作るので、いまの機体ではまだ端末の道を通らない（家の言葉が家の窓を持つことだけが、いまの動きに効く）。

1-ろ-2 でできたことは次のとおりである。

- 端末の求めの返事は、家のスピーカーで声にせず、家の画面にも出さず、端末の受け手（`InformationProcessing.set_device_listener`）へ字で送る（種類 `say`。声にする字 `text` はト書きを外して声のタグを残し、画面に出す字 `display` は両方外す。家の声と画面と同じ扱い）。声を出す口（`_say_aloud`）と表示の口（`_emit`）の 2 か所で分ける。時間切れの一言（録音）も、深く調べるかの問いも、確認の問いも、同じ口を通る。
- 考え中の電子音は家で鳴らさず、いまの合図の種類が変わったときだけ端末へ送る（種類 `cue`・b1）。話しかけたときの機械音と、黙る音も、端末の求めでは家で鳴らさない。
- 求めが閉じたら、端末へ知らせる（種類 `closed`）。返事の無いまま閉じても、端末が待ち続けない。送るのは、求めが閉じる所、開いている求めを打ち切った所、例外などで閉じる所に届かずに終わった所である（閉じたあとの打ち切りでは送り直さない）。打ち切りは、待つあいだに次の求めが始まっても、打ち切った求めの端末へ送る。打ち切られた求めの返事は、あとから端末へ送らない。
- 深く調べるかの問いは求めが閉じたあとに言うので、端末の求めでは問わない（閉じたと知らせたあとに問いが届かないようにする）。
- 端末への返事では、家の話者の持ち時間を延ばさない（家で声にしていない）。
- 家の声や合図が鳴っていても、端末へは合図の種類を送る。
- 声にしない独り言（say の無い素の字）は、端末へも送らない（端末は届いた字を声にする）。
- 端末の言葉は、家の画面に「受けた」「聞いていない」を出さない。
- 端末の求めでは、家で音が出る道具（タイマー、アラーム、ストップウォッチ、音楽、印刷）と、確認の答え（`confirm`・`decline`）を、調停の候補にも主LLM の道具にも出さない。呼ばれても断り、使えなかったとして返す（`actions._HOME_ONLY_ACTIONS`）。
- 端末の言葉で「黙って」と頼まれ、軽く返す道になったら、「この端末からは、家のパジュを静かにできないよ。」と返す。家が黙っているときに「話していいよ」と言われたら（調停が解くと読んだか、言葉が解く言い方なら）、「この端末からは、家のパジュが静かにしているのを解けないよ。」と返す（家の黙る依頼は 1-ろ-1 どおり掛けも解きもしない）。
- 受け手はまだ誰も登録しない（待ち受けの口は 1-ろ-4）。端末の道は、いまの機体ではまだ通らない。
- 能力の一覧（`capabilities.yaml`）は、端末と話せることを書くのと一緒に 1-ろ-4 で直す。いまは端末の求めが届かず、端末の求めに道具の定義も出さないので、パジュが使えない道具をすすめることは無い。

1-ろ-2 で残したことは次のとおりである。

- 端末の「黙って」「話していいよ」が主LLM の道（考えて返す）へ行くと、主LLM ができない約束をするおそれが残る。決まった言葉に替えたのは軽く返す道だけである。
- 家の画面の停止ボタンは、端末の求めのあいだも押せて、端末の求めを打ち切る（家から止められる）。
- 求めが閉じたあとも、求めの口（`Request.device`）は次の求めまで残す。外すと、閉じたあとの声が家で鳴る（端末の求めを家で声にするほうが、まちがいとして重い）。閉じたあとに声を出すのは深く調べるかの問いだけで、それは端末の求めでは問わない。
- 端末の求めでは、止める道具（タイマーを止める、音楽を止めるなど）も使わない。家で鳴っているタイマーを、端末からも家の声（窓が端末のものなら断る・1-ろ-1）からも止められないあいだがある。止める道具だけ通すかを本人に確かめたい。

## 7. 複数の求めの扱い（家とアプリ、アプリどうし・2026-11-25 本人の指示「その前に、複数の求めに対処する方針を決めなさい」）

### 7.1 いまの作り（コードを読んだ事実）

| 事実 | 根拠 |
|---|---|
| 求めは同時に 1 つ。主LLM が考えているあいだに届いた人の言葉は、名前があってもなくても待たせ（保留箱）、前の求めが閉じてから届いた順に答える | `event_loop._take_trigger`（規則 1〜3） |
| 調べものだけが飛んでいるあいだに届いた言葉は、いまの求めに「言い足し」として添える。話した人は見ない | `event_loop._attach_to_request`、`_joins_words` |
| 確認待ち（「〜でいいですか？」のあと）に届いた言葉は、その確認への答えとして読む | `_take_trigger` の `_confirming`、知-o |
| 話しかけない求め（見回り）は、届いた言葉で打ち切ってから答える | 決定ジ（`_quiet_request_open`） |
| 名前で開く窓と、窓の会話（続けて話した言葉を 1 つの最終版にまとめる）は、家の声のためのもの | `WakeWindow`、環-ar |

### 7.2 原因

いまの作りは、言葉の届く口が家の 1 つだけであることを前提にしている。アプリが加わると、別の口から届いた言葉が、いまの求めに混ざる。たとえば、外に居る人がアプリで言った「はい」が、家で別の人が聞かれている確認への答えとして読まれる。アプリの言葉が、家の求めに言い足しとして添えられる。

### 7.4 決めたこと（複数の求め）

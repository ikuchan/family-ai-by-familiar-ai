## 6. 端-b の設計方針（機体の外の口・2026-11-25 から本人と決めている）

### 6.1 いまの入口と出口（コードを読んだ事実）

| 事実 | 根拠 |
|---|---|
| 人の言葉は、声も打った言葉も、同じ入口（`push_utterance`）から 1 つの待ち行列に並ぶ。求めは同時に 1 つで、順に答える | `loop/event_loop.push_utterance`、`_take_trigger` |
| 打った言葉（入口の種類 `keyboard`）は、名前を呼ばれた言葉と同じに扱う（名前の窓を見ない） | `event_loop`（`named=… or source == "keyboard"`） |
| 返事は、家のスピーカーで声にし（`_say_aloud`）、画面へも出す（`_emit`）。打った言葉への返事も、家で声になる | `event_loop._speak`、`_emit` |
| 考えているあいだは、家のスピーカーで待ちの電子音と合図を鳴らす | `event_loop._beep_while_waiting`、`io/dif.play_cue` |
| 外の口を作る部品（待ち受けの `aiohttp.web`）は、いまの依存の `aiohttp` に入っている。依存は増えない | `pyproject.toml` |

### 6.2 原因と対応案

アプリから届いた言葉は、いまの入口にそのまま流すと、返事が家のスピーカーで声になり、電子音も家で鳴る。いまの作りには「この求めの返事をどこへ返すか」が無く、返事の出口がいつも家だからである。

対応案は、求めに**返事の行き先**（家か、どの端末か）を持たせ、アプリから届いた言葉の求めでは、返事の字を話しかけた端末へ返し、家の声と電子音を出さないことである。入口は、いまの打った言葉と同じ道（名前を呼ばれた言葉・話者を明示した言葉）を通す。

### 6.5 段 1-ろ の分け方と、できたこと

段 1-ろ は、外から届く口（待ち受け）を最後に作る。中の決まりが揃うまで、外から話しかけられないようにするためである。

| 段 | 中身 | 状態 |
|---|---|---|
| 1-ろ-1 | **窓の持ち主**と、別の口の言葉を断る門 | 済み（2026-11-25） |
| 1-ろ-2 | **返事の行き先**：端末の求めの返事を、家で声にせず端末へ返す。家の電子音と合図も鳴らさない | 済み（2026-11-25） |
| 1-ろ-3 | **話者**：端末で選んだ話者を、家のそばに居る人に数えずに、その求めの話者にする（b3） | 済み（2026-11-25） |
| 1-ろ-4 | **待ち受けの口**：端末の字と話者を受け、返事を送る口 | 済み（2026-11-25・口の形は §6.6） |

1-ろ-1 でできたことは次のとおりである。

- 窓のデータに持ち主（家は空、端末はその端末の名前・`WakeWindow.owner`）を持たせた。閉じた窓を開けた口が持ち主になり、開いているあいだは変わらない。ほかの口は開け直しも延ばしもできない。
- 門の最初（`_mouth_gate`）で、窓が開いていて持ち主が別の口なら、その口の言葉を名前があっても断る。家の言葉は、ログに残して捨てる（家の話し中の音は段 1-は・§6.7）。
- 端末の言葉は、端末の中で名前の合図を聞いてあるので、名前で呼ばれた言葉として受け、窓をその端末のものとして開ける。耳の入口と家の「黙って」は見ない（b4）。黙るのは解かず、黙っていたあいだに控えた家の言葉も、端末の求めへ渡さない。
- 口の違う言葉は、調べもの中の求めに添えず、考え直しにも見せず、その求めが閉じるまで待たせる。待たせた言葉を取り出すとき、窓がいま別の口のものなら断る。端末の求めでは、家で聞いた確認（タイマーを掛ける前など）の答えを読まない。
- 窓を保つのは、窓の持ち主の求めだけにした（頭のデータに求めの口を持たせた）。端末の窓のあいだに家の情動の求めが考えていても、端末の窓を保たない。家の求めは、端末の窓の会話を読まない。持ち主の変わる窓は、新しい窓の会話にする。
- 端末の求めは、家の「黙って」を調停に伝えず、掛けも解きもしない（b4）。
- 言葉を列から取り出すときにも、窓がいま別の口のものなら断る（門の中で Jev を待つあいだや、列で待つあいだに、別の口が窓を取ることがある）。窓の持ち主は、持ち主が窓を開けた時刻より前に話し始めた言葉には居なかったものとして見る。
- 窓の持ち主と求めの口は、状態ではなく窓と頭のデータ（閉じる時刻と同じ扱い）なので、状態図の領域と移りは増やしていない。
- 端末から言葉が届く口は 1-ろ-4 で作るので、いまの機体ではまだ端末の道を通らない（家の言葉が家の窓を持つことだけが、いまの動きに効く）。

1-ろ-2 でできたことは次のとおりである。

- 端末の求めの返事は、家のスピーカーで声にせず、家の画面にも出さず、端末の受け手（`InformationProcessing.set_device_listener`）へ字で送る（種類 `say`。声にする字 `text` はト書きを外して声のタグを残し、画面に出す字 `display` は両方外す。家の声と画面と同じ扱い）。声を出す口（`_say_aloud`）と表示の口（`_emit`）の 2 か所で分ける。時間切れの一言（録音）も、深く調べるかの問いも、確認の問いも、同じ口を通る。
- 考え中の電子音は家で鳴らさず、いまの合図の種類が変わったときだけ端末へ送る（種類 `cue`・b1）。話しかけたときの機械音と、黙る音も、端末の求めでは家で鳴らさない。
- 求めが閉じたら、端末へ知らせる（種類 `closed`）。返事の無いまま閉じても、端末が待ち続けない。送るのは、求めが閉じる所、開いている求めを打ち切った所、例外などで閉じる所に届かずに終わった所である（閉じたあとの打ち切りでは送り直さない）。打ち切りは、待つあいだに次の求めが始まっても、打ち切った求めの端末へ送る。打ち切られた求めの返事は、あとから端末へ送らない。
- 深く調べるかの問いは求めが閉じたあとに言うので、端末の求めでは問わない（閉じたと知らせたあとに問いが届かないようにする）。
- 端末への返事では、家の話者の持ち時間を延ばさない（家で声にしていない）。
- 家の声や合図が鳴っていても、端末へは合図の種類を送る。
- 声にしない独り言（say の無い素の字）は、端末へも送らない（端末は届いた字を声にする）。
- 端末の言葉は、家の画面に「受けた」「聞いていない」を出さない。
- 端末の求めでは、家で音が出る道具（タイマーとアラームの止め方・一時停止、ストップウォッチ、音楽、印刷）と、確認の答え（`confirm`・`decline`）を、調停の候補にも主LLM の道具にも出さない。呼ばれても断り、使えなかったとして返す（`actions._HOME_ONLY_ACTIONS`）。タイマーとアラームを掛ける道具（`set_timer`・`set_alarm`）は、端-c c6a から、頼んだ端末の時計アプリへ頼む（§8.8）。音楽をかける道具（`play_music`）は、端-c c6b 段 1 から、頼んだ端末の Spotify で開く（§8.9）。
- 端末の言葉で「黙って」と頼まれ、軽く返す道になったら、「この端末からは、家のパジュを静かにできないよ。」と返す。家が黙っているときに「話していいよ」と言われたら（調停が解くと読んだか、言葉が解く言い方なら）、「この端末からは、家のパジュが静かにしているのを解けないよ。」と返す（家の黙る依頼は 1-ろ-1 どおり掛けも解きもしない）。
- 受け手はまだ誰も登録しない（待ち受けの口は 1-ろ-4）。端末の道は、いまの機体ではまだ通らない。
- 能力の一覧（`capabilities.yaml`）は、端末と話せることを書くのと一緒に 1-ろ-4 で直す。いまは端末の求めが届かず、端末の求めに道具の定義も出さないので、パジュが使えない道具をすすめることは無い。

1-ろ-2 で残したことは次のとおりである。

- 端末の「黙って」「話していいよ」が主LLM の道（考えて返す）へ行くと、主LLM ができない約束をするおそれが残る。決まった言葉に替えたのは軽く返す道だけである。
- 家の画面の停止ボタンは、端末の求めのあいだも押せて、端末の求めを打ち切る（家から止められる）。
- 求めが閉じたあとも、求めの口（`Request.device`）は次の求めまで残す。外すと、閉じたあとの声が家で鳴る（端末の求めを家で声にするほうが、まちがいとして重い）。閉じたあとに声を出すのは深く調べるかの問いだけで、それは端末の求めでは問わない。
- 端末の求めでは、止める道具（タイマーを止める、音楽を止めるなど）も使わない。家で鳴っているタイマーを、端末からも家の声（窓が端末のものなら断る・1-ろ-1）からも止められないあいだがある。それでよい（2026-11-25 本人「止められなくていいです」）。

1-ろ-3 でできたことは次のとおりである（決まりの正本は `設計方針_在席と顔ぶれ` §6d）。

- 端末で押した話者の名前を、言葉と一緒に受けて（`push_utterance` の `speaker`）、その求めのデータ（`Request.speaker`）に持たせる。
  家の話者の状態（顔ぶれの表、明示の話者、話者の時刻）には書かない。
- 話者を読む口（想起の面、会話の記録の書き手、呼び名、口調、思い出す道具が引く人の記憶、道具の `speaker`）は、端末の求めのとき
  だけ端末の話者を読む。求めのあいだは寿命で切れない。家族に当たらない名前は「誰か分からない」にし、家の話者を借りない。
- 求めが閉じたら端末の話者を外す。会話の要約は閉じる前の書き手で、思い出す道具は投げたときの求めで、記憶を引く人を決める。
  家の話者の寿命は、端末の求めのあいだも家の印だけで決める。
- 主LLM には、家の顔ぶれの代わりに、端末から話している話者の名前を渡す（家のそばに居るとは限らない、と添える）。
- 端末の言葉の「〇〇じゃない」で、家の顔ぶれを変えない。
- 端末の会話の記録には、家のそばに居る人を添えない〔仮（本人の確認待ち）〕。主LLM に添える言い回しも仮である。
- 端末の求めでは、本人の道具（vault・journal）を開けない。端末で押した話者は、顔や声で確かめていないためである〔仮（本人の確認待ち）〕。
- 黙っていたあいだに家で聞いた言葉は、端末の求めが開いていても家の話者のものとして残す。
- 端末から言葉が届く口は 1-ろ-4 で作った（§6.6）。

1-ろ-3 で残したことは次のとおりである。

- 同じ端末で、求めの途中に別の話者を押して言い足しても、言い足しは求めの話者（最初に押した人）のものになる。
- 範囲を広げて思い出す道具（`recall_as` など）は、走るときの求めで面を決める（記憶を引く人を投げたときに決めたのは `recall` だけ）。閉じた求めの調べものの結果は次の求めに取り込まないので、取り違えが返事に出ることはない見込みである〔推測〕。
- もとからの不具合：閉じる所に届かずに終わった求めは開いたままなので、同じ求めで 2 度例外が起きると、端末へ「閉じた」を 2 度送る。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 端末の言葉も、キーボードの言葉と同じく、返すか黙るかの判定（出-db 段 E）を通さない | 端末が名前の合図を聞いてから送る話しかけで、テレビの声や崩れた書き起こしは来ない |
| 端末の求めでは、家で聞いた確認を見ない。確認を聞く道具（タイマー、アラーム、印刷）は、端末の求めでは使わない（1-ろ-2 で止める） | 確認を聞くのは家の求めだけにして、口の違う言葉を確認の答えに読まない |
| 端末が窓を持つあいだは、家の言葉を、タイマーや音楽を止める言葉と「話していいよ」も含めて断る | §7.4 の「ほかの口の言葉は断る」どおり。止める言葉だけ通すと、端末の求めが閉じるまで待つことになり、すぐには止まらない。止める道具は、端末からも使わない（端末と話しているあいだ、家で鳴っているタイマーを止められなくてよい・2026-11-25 本人の決定） |
| 端末の言葉で「黙って」と頼まれても、家の黙る依頼は掛けない。返事の言葉の扱い（黙ると言ってしまわないか）は 1-ろ-2 で見る | b4 は家で声を出さない頼みで、端末から家を黙らせる決まりは無い |
| 1-ろ-2：端末の求めでは、家の音を扱う道具（タイマー、アラーム、ストップウォッチ、音楽。止める・音量も含む）、印刷、確認の答えを使わない。頼まれたら、使えなかったと返す。タイマーとアラームを掛けるのは、端-c c6a から端末の時計アプリへ頼む（§8.8） | b2（端末で鳴らす）の作りができるまで、家で鳴らさない（b1・§4 の 3）。確認の答えは 1-ろ-1 の続き |
| 1-ろ-2：端末から「黙って」と頼まれたら「この端末からは、家のパジュを静かにできないよ。」と返す（軽く返す道のとき） | 家を黙らせないのに「静かにするね」と約束しない（b4） |
| 1-ろ-2：考え中の合図は、種類が変わったときだけ端末へ送る。声にしない独り言は送らない | 端末が合図の音を持つ（b1）。端末は届いた字を声にするので、独り言を送ると声になる |
| 断った家の声は、名前で呼ばれた情動の押し上げも、家族の話の記録（記-ae 段 4）もしない。知らない声の気配（SAFETY）は、断る前に見るので残る | 断る門を短く保つ |
| 端末の窓のあいだに家の求め（情動、機器）が始まっても、その求めは端末の窓を保たず、窓の会話も読まない | 窓を保つのは持ち主の求めだけ（§7.4「持ち主の求めが開いているあいだ」） |
| 1-ろ-4：待ち受けるのは機体の中（127.0.0.1）だけ、ポートは 8765、1 回に受ける字は 2000 字まで、端末と話者の名前は 32 字まで | 家族の端末から入る道（Tailscale）は端-d で作る。それまでは外から話しかけられない |
| 1-ろ-4：Origin を付けたつなぎ（ブラウザのページ）は断る。入口を待つ言葉は 1 台につき 3 つまでで、それより多ければ断ったと返す | 家族の端末のアプリは Origin を付けない。機体で開いたページから家族の名前で話しかけられ、その人の記憶から作った返事を読まれないようにする。多すぎる言葉で家の列を埋めない |
| 1-ろ-4：同じ名前の端末が 2 本目をつないだら、古いほうを閉じる | 端末ごとに返事の送り先を 1 つにする（アプリを開き直したとき、古いつながりが残っていることがある） |
| 1-ろ-4：求めの途中で端末が切れても、求めは打ち切らず、窓も手放さない。返事は送り先が無いので捨てる | 切断で打ち切ると、そのとき開いている別の求めを消すおそれがある。窓は持ち主の求めが閉じれば閉じる（1-い） |

### 6.6 待ち受けの口の形（1-ろ-4・端-c が使う）

端末は機体の `ws://〈番地〉:8765/device?name=〈端末の名前〉` に WebSocket でつなぐ（`io/device_link.py`・設定は
`config.DeviceLinkConfig`）。端末の名前は、その端末の返事の送り先の名前で、空は家の印なのでつながせない。字はすべて JSON で送る。

| 向き | 種類 | 中身 | いつ |
|---|---|---|---|
| 端末 → 機体 | `say` | `{"type": "say", "text": 言葉, "speaker": 押した話者の名前}` | 名前の合図を聞いたあとの言葉（書き起こしか、打った字） |
| 機体 → 端末 | `hello` | `{"type": "hello", "voice": {"model": 合成のモデル, "voice": 声の種類}, "names": パジュの呼び名, "speakers": 家族の呼び名, "busy": 話せないか}` | つないだすぐあと。鍵は送らない（§4 の 3 の続き）。`names` は端末が名前を呼ぶ合図に使う呼び名（`config.agent_names`）、`speakers` は話者のボタンに並べる家族の呼び名（FAMILY.md の 1 人 1 つ・`rest_fold.family_call_names_of`）で、つなぐたびに読む（`/reload` で読み直したものも伝わる・端-c c2）。`busy` は下の `window` と同じ |
| 機体 → 端末 | `say` | `{"type": "say", "text": 声にする字, "display": 画面の字}` | 返事 |
| 機体 → 端末 | `cue` | `{"type": "cue", "kind": 合図の種類}` | 考え中の合図の種類が変わったとき（b1） |
| 機体 → 端末 | `closed` | `{"type": "closed"}` | 求めが閉じた・打ち切った（返事の無いまま閉じても待ち続けない） |
| 機体 → 端末 | `refused` | `{"type": "refused"}` | 届いた言葉を断った（窓が家かほかの端末のもの） |
| 機体 → 端末 | `window` | `{"type": "window", "busy": 話せないか}` | その端末の「話せないか」が変わったとき（1-は）。窓が開いていて持ち主が家かほかの端末なら真で、端末は話す画面をグレーにする。誰と話しているかは送らない |
| 機体 → 端末 | `timer` | `{"type": "timer", "seconds": 秒（1〜86400）, "label": 名前}` | 端末の求めでタイマーを頼まれたとき。端末は時計アプリへ渡す（端-c c6a・§8.8） |
| 機体 → 端末 | `music` | `{"type": "music", "uri": Spotify の URI か空}` | 端末の求めで音楽を頼まれたとき。端末は Spotify のアプリで開き、空なら Spotify を開くだけ（端-c c6b 段 1・§8.9） |
| 機体 → 端末 | `alarm` | `{"type": "alarm", "hour": 時（0〜23）, "minute": 分（0〜59）, "label": 名前}` | 端末の求めでアラームを頼まれたとき。時と分は端末の時刻で、過ぎていれば翌日に鳴らすのは時計アプリ（端-c c6a・§8.8） |

- 機体は、受けた言葉を入口（`push_utterance`）へ端末の言葉として流す。読む輪は入口を待たない（入口は最初の反復が終わるまで
  返らない）。家の命令（`/speaker`、頭の `[名前]`）は読まない（端末の話者は押した話者・b3）。
- 返事は、受け手に渡った順にその端末へ送る（返事のあとに閉じた、の順が入れ替わらない）。つながっていない端末への返事は捨てる。
- 読めない字と知らない種類は捨て、つながりは切らない。空か長すぎる言葉と、字でない言葉は `refused` を返す（端末が返事を待ち続けない・端-c c1 の見直しで足した）。
- 端末の言葉は、門で捨てたらいつも `refused` を返す（`_swallowed`）。門を通った言葉は、求めが閉じたら `closed` が届く。
- ログには、端末の名前を印に、言葉を字数にして出す。
- 待ち受けの番地を取れなくても、起動は止めない（WARNING を 1 行残す）。

1-ろ-4 で残したことは次のとおりである。

- いまは機体の中でしか待ち受けないので、家族の端末からはまだつながらない（端-d）。
- 端末の名前と押した話者は、端末の申告をそのまま使う。機体の中で動く別のプログラムは、どの端末の名前でもつなげ、同じ名前の端末を追い出せる。家族の端末かどうかを確かめる鍵（`.env` に置く資格情報）は、外から入れる道（端-d）を開ける前に足す。
- 求めの途中で切れた端末がつなぎ直しても、切れていたあいだの返事は届かない。
- 機体を止めるとき、待たせていた端末の言葉には `refused` を送らない（端末にはつながりが切れたことだけが届く）。送り終えていない返事は、1 秒だけ待ってから止める。
- 端末のアプリ（端-c）は Origin を付けずにつなぐ。付ける作りの部品を選んだら、ここを見直す。

### 6.7 段 1-は：家の話し中の音と、窓の持ち主の知らせ（できたこと）

§7.4 の「家での断り方」と「端末での断り方」を作った。

- **家の話し中の音**：窓が端末のものなのに家でパジュに話しかけられたら、家のスピーカーで短い話し中の音（プップッ・
  `sounds/react_busy.wav`）を 1 回鳴らす。作り置きの音で、主LLM も声の合成も通さない。門は鳴り終わりを待たない。鳴っているあいだに
  また断っても重ねない（`DIF.play_busy`）。
  - 断るのは門（`_mouth_gate`）と、列から取り出すとき（`_owned_by_another`）の 2 か所で、どちらも 1 つの口（`_refuse_other_mouth`）で
    断る。端末の言葉なら `refused` を返し、家の言葉なら話し中の音を鳴らす。
  - 口の門を、考えているあいだの門より前に置いた。端末の求めのあいだ耳は「考えているあいだ聞かない」にいるので、前の順では
    家の名前の声を黙って捨てていた。耳の入口（音楽・タイマーの言葉だけ）と知らない声は、いままでどおり口の門より先に捨てる。
- **窓の持ち主の知らせ**：状態図は、窓を開けた・延ばした・切れたあとに、いまの持ち主（閉じていれば無し）をデータから読んで I へ
  渡す（`PajuState.on_window_owner`）。I は端末の口へ渡し（`set_window_listener`）、端末の口は各端末へ、その端末の「話せないか」が
  変わったときだけ `window` を送る（§6.6）。切れたと送っているあいだに開け直された窓も、古い時刻で開けてもう切れていた窓も、
  いまの持ち主で伝わる。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 話し中の音は、1 つ下のラ（約 436 Hz）を 0.10 秒、0.10 秒あけてもう 1 回。大きさは単音の電子音と同じ −6 dB | 電子音と同じ 1 つの音階から取る。電話の話し中の音に近い低めの短い 2 音 |
| 鳴らすのは、窓が空いていれば窓を開けた家の言葉だけ（名前で起こせる声と、キーボードの字）。名前の無い声と 1 字違いの名前の声には鳴らさない | 家族どうしの話やテレビの声にまで鳴らさない |
| 家が黙っているよう頼まれているあいだは、話し中の音を鳴らさない | 黙っているあいだは家で音を出さない決まり（§7.4 で、実装計画で決まりと照らすとした所） |
| 列で待つあいだに端末が窓を取って断った家の言葉にも、話し中の音を鳴らす | 門を通った、パジュに話しかけた言葉なので |

## 7. 複数の求めの扱い（家とアプリ、アプリどうし・2026-11-25 本人の指示「その前に、複数の求めに対処する方針を決めなさい」）

### 7.1 いまの作り（コードを読んだ事実）

| 事実 | 根拠 |
|---|---|
| 求めは同時に 1 つ。主LLM が考えているあいだに届いた人の言葉は、名前があってもなくても待たせ（保留箱）、前の求めが閉じてから届いた順に答える | `event_loop._take_trigger`（規則 1〜3） |
| 調べものだけが飛んでいるあいだに届いた言葉は、いまの求めに「言い足し」として添える。話した人は見ない | `event_loop._attach_to_request`、`_joins_words` |
| 確認待ち（「〜でいいですか？」のあと）に届いた言葉は、その確認への答えとして読む | `_take_trigger` の `_confirming`、知-o |
| 話しかけない求め（見回り）は、届いた言葉で打ち切ってから答える | 決定ジ（`_quiet_request_open`） |
| 名前で開く窓と、窓の会話（続けて話した言葉を 1 つの最終版にまとめる）は、家の声のためのもの | `WakeWindow`、環-ar |

### 7.2 原因

いまの作りは、言葉の届く口が家の 1 つだけであることを前提にしている。アプリが加わると、別の口から届いた言葉が、いまの求めに混ざる。たとえば、外に居る人がアプリで言った「はい」が、家で別の人が聞かれている確認への答えとして読まれる。アプリの言葉が、家の求めに言い足しとして添えられる。

### 8.4 段 c1：アプリの中の決まり（できたこと）

`android/core`（Kotlin・Android を読まない・機体の JVM で `gradle :core:test`）に置いた。部品は入れていない（Kotlin の標準だけ）。

- **口の字の読み書き**（`Wire`）：機体から届く 6 種類（§6.6 の hello・say・cue・closed・refused・window）を型にして読む。読めない字、
  知らない種類、欠けた値は捨てる（機体と同じく、つながりは切らない）。送る字は `say`（言葉と押した話者）で、前後の空白を落とす。
  空の言葉、2000 字を超える言葉、32 字を超える話者は送らない（機体の端末の口が断る言葉）。字の数え方（絵文字も 1 字）と、落とす空白の字は機体（Python）に合わせた。深すぎる入れ子の字は読めない字として捨てる。字の読み書きは小さな JSON（`Json`）で、
  口の字が平たいので部品を入れずに書いた。
- **名前を呼ぶ合図**（`Wake`）：書き起こしを、名前で始まり言葉が続く（送る）、名前だけ（送らず、続く言葉を聞く・c3）、話しかけて
  いない（送らない）の 3 つに分ける。機体の門の決まりに合わせた。ゆるい読み（カタカナはひらがな、長音と濁点を落とす、小書きは
  大きく）で比べ、文頭の空白と記号だけを飛ばす（「ねえパジュ」は当たらない）。名前だけの繰り返しは送らない。
- **話す画面の状態**（`Talk`）：つながっていない、話せる、グレー（窓が家かほかの端末のもの）、返事を待つ、の 4 つ。届いた字と、
  送った・切れた、だけで変わる。窓が家のものになれば、返事を待っていてもグレーにする。いまの話者は、代えるまで、つなぎ直しても
  同じ人のまま（§4 の 5）。
- **口の形の見本を機体と共有する**：`tests/data/device_wire.json` に、機体が送る字（`json.dumps` の字そのまま）、アプリが送る字、
  名前の合図の例を置いた。機体の試験（`tests/test_device_wire_is_shared.py`）は、端末の口が送る字が見本と 1 字も違わないこと、
  見本の字を言葉と話者として受けること、合図の例が門の文頭の名前の決まりと同じことを見る。アプリの試験（`WireFixtureTest`）は
  同じ見本を読む。どちらかが口の形を変えれば、もう一方の試験が落ちる（両方で、見本を 1 字変えて落ちるのを確かめた）。

c1 で残したことは次のとおりである。

- 1 字違いの名前（「パジョ」「カジュー」）は、端末では聞き分けない。機体はこれを Jev に確かめてから通すが、端末にはその道が無い。
  名前に続けて 1 字違いの名前を言った言葉（「パジュ、カジュー」）は、機体の門なら繰り返しとして捨てるが、端末は送る。
- 端末がつなぎ直すと「返事を待つ」を解くが、機体は前の求めを続けていて、その返事と `closed` があとから届くことがある。返事を待ち続けないための時間切れと合わせて、時計を持つ c2 の画面で扱う。
- 端末の言葉を入口へ流す仕事が例外で終わると、端末の口はログに残すだけで、端末へは何も返さない。
- 口の形の見本は、端末の口（`io/device_link.py`）の字を見る。I から端末へ渡す種類と中身（`event_loop` の `_to_device`）は、
  端-b の試験が見ている。

### 8.5 段 c2：アプリの殻（できたこと）

`android/app`（Android・Kotlin・標準の View）に置いた。部品は OkHttp 4.12.0（WebSocket・2026-11-25 本人の承認）だけで、組み立ては
機体の手元にある部品で済んだ（新しく取ってきたものは無い）。OkHttp の WebSocket は、つなぐときに Upgrade・Connection・
Sec-WebSocket-Key・Version・Extensions だけを付け、Origin は付けない（部品の中身で確かめた）。

- **機体の側**：端末の口は、`hello` に、パジュの呼び名（`names`）と、話者のボタンに並べる家族の呼び名（`speakers`）を添える
  （§6.6）。つなぐたびに読むので、`/reload` で読み直した FAMILY.md も次につないだ端末へ伝わる。アプリに家族の名前は書かない。
- **画面**：話者のボタン、返事の字（送った言葉とパジュの返事を並べる）、字の入力と送るボタン、設定（機体の番地とこの端末の名前）。
  - スマホは 1 列で、話者のボタンを上に横へ並べる。タブレット（短い辺が 600 dp 以上）は、話者のボタンを左にいつも見える所へ
    縦に並べる。
  - 話せないとき（つながっていない・窓が家かほかの端末のもの）は、入力と送るボタンを押せなくし、薄くする（グレー・§7.4）。
    断られたら「（いまは話せません）」と出す。
  - いまの話者は、ボタンを押すまで同じ人のまま（端末に残す）。機体から届いた家族に居ない人は、いまの話者から外す。
  - 返事の声はまだ出さない（字だけ・c5）。考え中の合図もまだ鳴らさない（c4）。
- **つなぎ**：番地（名前・IPv4・IPv6、ポートは省けば 8765）から `ws://番地:ポート/device?name=端末の名前` を作る（`core/Address`）。
  空白や道の入った番地、おかしいポートは使わない。画面を開いているあいだだけつなぎ、切れたら（機体が閉じたときも）3 秒ごとに
  つなぎ直す。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 機体の番地・この端末の名前・いまの話者は、その端末の中にだけ残す（Android の設定の置き場） | 端末ごとの設定（§4 の 7 の続き）。機体の保存（PostgreSQL）の決まりは機体のもので、端末の設定は機体へ送らない |
| この端末の名前は、入れなければ端末の機種名（32 字まで） | 名前の無い端末はつなげない（§6.6）。同じ機種が 2 台あれば、設定で名前を分ける |
| 返事を待つのは、送ってから 3 分まで。過ぎたら話せる画面に戻す | 機体の返事が来ないまま（求めが例外で終わったなど）待ち続けない。調べものの長い求めでも 3 分は超えない見込み〔推測〕 |
| 機体へは暗号を掛けない `ws://` でつなぐ | 家の外からは Tailscale の通り道（端-d）が暗号にする。家の中のネットワークでは暗号が無い |
| 画面を開いているあいだだけつなぐ | 持ち歩くスマホは画面を開いているときだけ聞く（§4 の 7 の続き）。ずっと聞く端末は、画面を消さずに開いたままにする（§8.6） |

c2 で残したことは次のとおりである。

- 端末を機体につないでいないので、実機ではまだ動かしていない。確かめるときは、動いているパジュにはつながず、偽の入口で立てた
  口へ `adb reverse` でつなぐ（§8.3）。
- 画面は、組み立てが通ることだけを確かめた。画面の決まり（話せるか・グレーか・待つか）は `core/Talk` の試験で見ている。
- 端末と機体のあいだに鍵は無い。機体の中だけで待ち受けているので、家族の端末からはまだつながらない（端-d）。

### 8.6 段 c3：声で話す（できたこと）

- **送る言葉を選ぶ**（`core/Listen`・JVM で試験）：書き起こしを、名前を呼ぶ合図（`Wake`）で分ける。
  - 名前で始まる言葉は、書き起こしのまま（名前も付けたまま）送る。
  - 名前だけなら送らず、続く 10 秒の言葉を名前なしで送る。機体が名前だけで黙って窓を開けるのと同じ。
  - 返事が届いた・求めが閉じたあとも、10 秒は名前なしの言葉を送る（§7.4「会話が続くあいだ」）。送れた言葉（声でも字でも）も
    そこから 10 秒延ばす。送れなかった言葉（長すぎた・切れていた）は延ばさない。
  - 10 秒は、言い終えた時刻でなく話し始めた時刻で見る（10 秒の中で話し始めた長い言葉を落とさない）。
  - 返事を待つあいだも、名前なしの言葉は、送った言葉から 10 秒だけ受ける。
  - 話せないとき（つながっていない・グレー）は送らない。切れた・窓がほかの口のものになった・画面を閉じたら、会話もそこで切る。
    名前だけの繰り返し（「パジュパジュ」）は、会話の中でも送らない。
- **窓の長さを機体と揃える**：機体は、端末へその端末の窓が開いているかを送らない（`window` はほかの口の窓だけを知らせる）。
  そこでアプリが同じ長さを自分で数える。長さは口の形の見本（`tests/data/device_wire.json` の `window_sec`）に置き、機体の試験は
  `WAKE_WINDOW_SEC` と、アプリの試験は `Listen` の長さと同じかを見る。
- **耳**（`app/Ear`）：端末の中で書き起こす音声認識（Android 12 から）で、日本語を聞き続ける。聞き終えるたびに聞き直す。
  認識の働き手が落ちたら作り直し、続けて 5 回うまくいかなければ聞くのをやめる。マイクの許しは、初めて画面を開いたときに
  1 度だけ求める（端末に残す）。断られたとき、端末の中で書き起こせないとき、日本語が入っていないときは、その旨を 1 度だけ出して、
  アプリを動かしているあいだは字だけで話す。音は端末の外へ出さない。
- **端末ごとの設定**：設定に「ずっと聞く」を置いた。入れた端末は、アプリを開いているあいだ画面を消さない。入れない端末は、
  画面が消えるかほかのアプリへ移ると聞くのをやめる（つなぎも切る）。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 「ずっと聞く」は、アプリを開いたまま画面を消さないことにする。画面を消して聞き続ける作り（マイクを使う常駐の働き）にはしない | 画面を消して聞くには、つなぎと話す状態を画面の外へ移す大きな作りが要る。充電して置くタブレットなら画面を点けたままでも困らない見込み〔推測〕。家族から見ると、タブレットの画面がずっと点いている |
| 書き起こしは、端末の中で書き起こせる認識だけを使う。無い端末（Android 11 まで・入っていない端末）では声で話せず、字で話す | §4 の 4（書き起こしはスマホでする）。ふつうの認識は音を外のサービスへ送ることがある |
| 名前で始まる言葉は、名前を付けたまま送る | 機体は端末の言葉に名前を求めないので、外しても付けても届く。書き起こしを変えないほうが単純 |
| 会話が続くあいだは、返事か閉じたか送れた言葉から 10 秒（機体の窓と同じ長さ） | §7.4。機体と違う長さにすると、送った言葉が機体の窓の外で届く |
| 返事を待つあいだの名前なしの言葉は、送った言葉から 10 秒だけ受ける | 機体は求めが開いているあいだ窓を閉じない（§7.4）が、長い調べもののあいだ、そばの話し声（テレビ・家族どうし）を送り続けると、機体の待ち（1 台 3 つまで）があふれて断られる |

c3 で残したことは次のとおりである。

- 実機ではまだ動かしていない。端末によっては、聞き始めるたびに認識が短い音を鳴らすことがある。聞き直しの間（0.2 秒、
  うまくいかなかったときは 1 秒）も、実機で確かめる。
- 返事の声（c5）を出すようになったら、声を出しているあいだは耳を止める（自分の声を聞かないように）。
- 1 字違いの名前は、端末では聞き分けない（§8.4 のまま）。
- マイクの許しをあとから端末の設定で入れたときは、アプリを動かし直すまで聞かない。

### 8.7 段 c4：考え中の合図を端末で鳴らす（できたこと）

- **いつ鳴らすか**（`core/Talk` の `beep`）：機体は、端末の求めのあいだ家で電子音を鳴らさず、考えているの子が変わったときに
  その種類だけを送る（`cue`・b1）。端末は、`cue` が届いてから、その種類の電子音を鳴らし続ける。止めるのは、返事が届いた
  （答えを言うあいだは鳴らさない・機体と同じ）、求めが閉じた、断られた、切れた、返事を待つ時間切れ、のとき。返事のあとに
  また考えて `cue` が届けば、また鳴らす。知らない種類と、返事を待っていないとき（時間切れのあと）に届いた合図は鳴らさない。
- **機体の側**：機体は合図の種類が変わったときだけ `cue` を送るが、端末へ返事を送ったあとは、同じ種類のままでももう一度送る
  （端末は返事で合図を止めるので、途中の返事のあとも考え続けるなら鳴らし直せるように・`event_loop._beep_while_waiting`）。
- **何を鳴らすか**（`core/Beeps`）：種類ごとの音（思い出す・決める・待つ・確かめる・書き留める）と、鳴らし始めから次までの
  1 秒は、機体の音（`core/reaction_cue.BEEP_WAVS`）と間隔（`wait_beep_interval_seconds` の既定）と同じ。口の形の見本
  （`beeps`・`beep_interval_sec`）に置き、機体の試験とアプリの試験の両方が見る。
- **音のファイル**：アプリの組み立てのときに、機体の `src/familiar_agent/sounds/` から写す（`copyBeeps`）。写しはリポジトリに
  置かないので、機体の音を作り直せば、次に組み立てたアプリも同じ音になる。写すのは見本の `beeps` に書いた音だけで、1 つでも
  無ければ組み立てを止める。音は端末の声の助け手の音として、端末の音量で鳴らす。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 端末の合図は、端末の声の助け手の音（Android の音の使い道の 1 つ）として、端末の音量のまま鳴らす | 機体は電子音を元の大きさ（倍率 1.0）で鳴らす。端末の音量は持ち主が決める。システムの音は切っている端末が多く、聞こえないことがある。返事の声（c5）も同じ使い道にする |

c4 で残したことは次のとおりである。

- 実機ではまだ鳴らしていない。声の助け手の音がどの音量のつまみに従うかは端末による。音の大きさと、鳴った電子音を端末の耳が書き起こさないか（名前で始まらないので送らない見込み〔推測〕）は、実機で確かめる。

### 8.8 段 c6a：端末のタイマーとアラーム（できたこと）

- **掛ける場所**：端末の求めの `set_timer`・`set_alarm` は、家のタイマーとアラームに入れず、頼んだ端末へ `timer`（秒と名前）か
  `alarm`（時と分と名前）を送る（§6.6・`event_loop._device_clock`）。端末は、届いたらすぐ（§8.9 の「渡す時機」）Android の時計アプリへ渡し（`AlarmClock` の
  タイマーとアラームの頼み・確かめの画面を出さない）、鳴らすのも止めるのも時計アプリである。パジュのアプリは数えないので、
  アプリを閉じても鳴る。家では鳴らず、家の確かめも、鳴るまで黙ることも置かない。
- **時刻の読み方**（`core/device_clock.clock_order`）：「何分後」「何時に」の読み方と名前の検めは、家の道具と同じもの
  （`timer_rules`・`alarm_rules`・`label_rules`）を使う。タイマーは 1 秒から 24 時間まで（時計アプリが受ける長さ）で、
  外れたら送らずに理由を返す。アラームは時と分だけを送り、過ぎた時刻を翌日に鳴らすのは時計アプリに任せる。アプリも同じ範囲の
  外と、整数でない数を捨てる（`Wire`）。
- **1 つの求めで 1 回まで**：頼めたら、その動作をその求めで使い切ったことにする（`spent_actions`）。家のタイマーは「同時に 1 本」で
  掛け直しを止める（主LLM が 1 回の頼みで 3 回掛けた・2026-09-21）が、端末の時計は機体から見えないので、この形で止める。
- **返り**：機体は端末の時計に掛かったかを知らない（端末から返りの字は無い）。主LLM への返りは「端末の時計アプリに頼んだ」と書き、
  掛けた、とは書かない。時計アプリが無い端末では、アプリの画面に「この端末の時計では掛けられません」と出す。
- **使わないまま**の道具：止める・一時停止・再開（`cancel_timer`・`pause_timer`・`resume_timer`・`cancel_alarm`）、
  ストップウォッチ、音楽、印刷、確認の答えは、いままでどおり端末の求めでは使わない（`actions._HOME_ONLY_ACTIONS`）。
- **許し**：アプリはアラームを掛ける許し（`SET_ALARM`）を宣言する。ふつうの許しで、本人に聞く画面は出ない。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 端末のタイマーとアラームは、端末の時計アプリで掛ける。パジュのアプリは自分で数えて鳴らさない | アプリは画面を開いているあいだしか機体とつながらず、閉じたあとに鳴らすには常駐の仕組みが要る。時計アプリなら閉じても鳴り、止めるのも時計アプリでできる（止める道具は端末から使わない・2026-11-25 本人の決定）。部品も足さない |
| 端末の求めでは、掛ける前に確かめない。静かな時間（23〜7 時）でも聞かない | 確認の答えは端末の求めでは読まない（1-ろ-2）。鳴るのは頼んだ端末だけで、家族を起こさない。端末の画面に掛けたことが出る |
| 端末のタイマーとアラームを、機体は覚えない（[タイマー]・[アラーム] の枠に出さず、記憶にも書かない。同時に 1 本の決まりも当てない） | 機体は掛かったかを知らず、端末で止めたことも届かない。覚えると、止めたあとも「動いている」と答える |

c6a で残したことは次のとおりである。

- 実機ではまだ掛けていない。時計アプリが確かめの画面を出さずに掛けるか、名前がそのまま出るか、時計アプリの無い端末で何が出るかは、端末をつないでから確かめる。
- 主LLM に見せる `set_timer`・`set_alarm` の説明は家のもの（確かめ・同時に 1 本）のままである。端末の求めでは返りの字が違うことを伝える。

- 端末の求めに `set_timer`・`set_alarm` を出すかは、家のタイマーとアラームの道具が使えるかで決まる（道具の定義は家のものを使う）。

### 8.9 段 c6b 段 1：端末の Spotify を開く（できたこと）

本人の答え（2026-11-26）：端末の Spotify のアカウントは、人や端末によって違う（家と同じアカウントの端末も、家族それぞれのアカウントの
端末もある）。段 1 は、どの端末でも使える「端末の Spotify を開いて曲を示す」を作った。家と同じアカウントの端末で機体が鳴らす段 2 は、
まだ作っていない。

- **探し方**：端末の求めの `play_music` は、家と同じ順（MUSIC.md・プレイリスト・ライブラリ・プレイリストに入っている曲とアーティスト・
  Spotify 全体）で探す（`MusicTool.find`・`_play` から探す部分だけを切り出した）。家の鳴らし方（`_play`・`_start`）は通らないので、
  spotifyd も家の機器も、鳴っている印も音量もランダムも触らない。
- **端末へ送る字**：見つけた URI を `music` で送る（§6.6・`event_loop._device_music`）。名前が無い（「音楽かけて」）ときは、家の続きを
  かけず、URI を空にして端末の Spotify を開くだけにする。見つからなければ送らずに断りを返す。1 つの求めで 1 回まで（c6a と同じ）。
- **返り**：機体は端末で鳴ったかを知らない。主LLM への返りは「端末の Spotify で開く（再生は端末で押してもらう）」と書き、かけた、とは
  書かない。
- **端末の側**（`Wire`・`Clock.open`）：Spotify の URI（`spotify:` のあとに空白の無い ASCII の字が 1 字以上・機体と同じ決まり）か空だけを受け、ほかの URI は捨てる（機体の
  字でほかのアプリやページを開かせない）。Spotify のアプリだけで開き（ほかに `spotify:` を受けるアプリがあっても渡さない。URI が空なら Spotify のアプリを起こす・`queries` に Spotify を書いた）、
  Spotify が無い端末では「音楽をかけられません」と画面に出す。
- **渡す時機**（`core/Talk`）：Spotify は、次に `closed` が届いたときに渡す。渡すと Spotify が前に出てパジュの画面が止まり、つながりが
  切れるので、先に渡すと、そのあとの返事と `closed` を受け取れない。機体は頼みをその求めの `closed` より先に送る（送りは 1 本の鎖）ので、
  次の `closed` がその求めのものである。返事を待つ 3 分の時間切れと、別の言葉が断られた（`refused`）ときは捨てない（機体はもう「開く」と
  言っている）。つながりが切れたら捨てる。時計（c6a）は、確かめの画面を出さず前に出ないので、届いたらすぐ渡す（遅らせると、切れたときに
  失い、数え始めも遅れる）。
- **返事**：家では鳴った音で分かるので、かけたあとは黙る。端末では、何を開いたか（読みから当てたものも）と、再生は端末で押すことを
  軽く伝える（`completion_kind.OPENED_ON_DEVICE`）。ランダムか順番かを頼まれたら、端末の Spotify のままで機体からは変えられないと返りに添える。
- **家の音楽を見せない**：端末の求めでは、調停にも主LLM にも家の `[音楽]` を見せず、家で鳴っていても曲名の無い `play_music` を落とさない
  （家で鳴っているから「もう鳴っている」と、端末の頼みを断らない）。
- **開けない URI**：見つけたものが Spotify の URI の形でなければ、送らずに断りを返す（端末は開かないので、「開く」と言わない）。
- **使わないまま**の道具：止める・次の曲・音量・すすめた曲への返事は、いままでどおり端末の求めでは使わない（端末の Spotify で操る）。

仮に置いた決定（本人の確認待ち）は次のとおりである。

| 決めたこと | 理由 |
|---|---|
| 端末では、ランダムか順番かを機体から決めない（端末の Spotify に任せる） | 開くだけでは、機体は端末の再生を操れない |
| 名前の無い「音楽かけて」は、端末の Spotify を開くだけにする | 家の続きは家のアカウントのもので、ほかのアカウントの端末には無い |
| Spotify を開くのは、求めが閉じてから（時計はすぐ） | 先に開くと、パジュの画面が止まって返事が届かない |
| 端末で「いま何の曲？」と聞かれても、家で鳴っている曲は答えない（読めないとして扱う） | 端末の Spotify で何が鳴っているかは機体に見えず、家の曲を答えると取り違える |

段 1 で残したことは次のとおりである。

- 実機ではまだ開いていない。Spotify が URI を開いたとき、自分で鳴り始めるか（本人が押すか）は、端末をつないでから確かめる。
- 家のアカウントの非公開のプレイリストは、ほかのアカウントの端末では開けないことがある〔推測〕。
- 段 2（家と同じアカウントの端末で機体が鳴らす）は、端末が Spotify の機器の一覧にどの名前で見えるかを実機で見てから作る。機器の名前は
  いま部分一致で探す（`spotify_web.device_id`）ので、段 2 では、家の機器（spotifyd）と取り違えないよう、ぴったり一致にして家の機器を外す。
  家の見回り（`now_playing`）がどの機器で鳴っているかを見ているかも、段 2 の前に確かめる（見ていなければ、端末で鳴ると家で鳴っていると思う）。

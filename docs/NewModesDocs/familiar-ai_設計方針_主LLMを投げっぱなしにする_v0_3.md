# familiar-ai 設計方針：主LLM を投げっぱなしにする（環-h・v0.3・未決なし）

## この文書の位置づけ

主LLM を**投げっぱなしの資源**として扱い、その返りを調べものの完了と**同じ道**（完了キュー
QC）で受ける。反復は「決める反復」と「出す反復」の2種類になり、`_iterate` は軽量LLM が
司る側だけを数える。

**課題8 の 環-f-ろ（主LLM を非同期にする）を含む。** 環-f-ろ はこの課題に吸収する。

**挙動が変わる。** 環-e（口を作り実体を切り出す・挙動を変えない）とは別に立てる。

実装はこの文書の承認後に始める。

## 1. なぜ

### いまの形

`_iterate`（271行）は、1つの反復の中で**軽量LLM の判断と主LLM の生成を同居**させている。
設計はこれを「**1つの work の内部二段**」と定め、「反復をまたがず別出力でもない」と明記して
いる（`I 内部設計根拠` 手順5）。

その結果、`_iterate` の出口は8つあり、**3つの軸**（誰が決めたか／声になるか／閉じるか）が
1つの関数に畳み込まれている。同じ結末が2か所ずつ書かれている。

| 結末 | 軽量LLM の側 | 主LLM の側 |
|---|---|---|
| 発話して閉じる | `:1274-1276` | `:1399-1401` |
| 調べものを投げて閉じない | `:1281-1293` | `:1358-1367` |
| 中止（世代ずれ） | `:1259-1261` | `:1352-1354` |

### 主LLM は既に資源である

**出-c（2026-09-04・完了）で、主LLM は `ModelResource` の型枠に乗った。** `設計図` ③-2 の
出入り口4つからも「**主LLM は 出-c で資源にしたので外れた**」と明記されている。

資源への投げっぱなしは、**既に QC を通る道がある**（`search_deferred`・`fetch_deferred`）。
主LLM だけが同期で居残っている。

### 主LLM の中で道具を使わせる形は採らない

「主LLM に道具を渡し、その内側でツールループを回す」形は、**この機体で 735 行として動いて
いて、環-c で撤去した**（`設計図` の撤去台帳）。設計も「**多段 ReAct はしない**」
（`イベント駆動ループ`）「**ターン内多段なし＝現行の主LLM↔ツールループを撤去**」
（`直近の進め方と進捗`）と名指しで排している。

戻さない理由は4つある。

| | 主LLM の内側で道具を回す | 投げっぱなしにする（本課題） |
|---|---|---|
| 打ち切り | **効かない**（`await` の切れ目が消える。実機で「打ち切った直後の反復が `fetch_deferred` を投げ、返事も1つ余計に出た」） | 効く（世代で捨てる・既存の仕組み） |
| W | **古いまま**（毎反復 O から作り直す原則が崩れる） | 毎反復 作り直す |
| `deferred` | **待つことになる**（検索は実測 平均2.5秒・最長22.1秒） | 投げっぱなしのまま |
| O の書き手 | **2つ**（ループの管理外で記録が増える） | ループだけ |

## 2. 対応

### 反復を2種類にする

| 反復 | 中身 | 軽量LLM | 数える |
|---|---|---|---|
| **決める反復** | 取込 → 想起 → 調停 → 出力（発話／調べもの投げ／**主LLM 投げ**） | 回す | **数える** |
| **出す反復** | 取込 → **主LLM の決定をそのまま実行**（発話 or 道具投げ）→ 閉じる | 回さない | **数えない** |

**`_iterations`（上限5）は軽量LLM を回した反復だけを数える。** 上限の意味が変わらない。

**「出す反復」で調停を回さない。** 回すと軽量LLM が主LLM の決定を覆せてしまい、「そのまま
出す」と矛盾する。主LLM の決定は決定として扱う。

### 主LLM へ道具を渡す

投げるときに、その反復の道具の定義（`_tools()` が組むもの）を一緒に渡す。上限に達した反復で
`say` だけに絞る現在の扱いも、そのまま持ち込む。

### 返りは QC で受ける

QC の要素は現在 `(語, 結果, 意図id, 種別, 番号)` で、**結果が文字列**である。主LLM の返りは
**道具の呼び出し**なので、QC が運べる形へ広げる。

### 記憶は残る

「出す反復」が `_speak` → `_finish` を通れば、いまとまったく同じものが書かれる。

| `_finish` が書くもの |
|---|
| `自分が答えた：…`（`direction="発話"`・役割 `答え`・親は求め） |
| やりとりの関係（`_close_exchange` で区間を切り出し、順序つきで束ねる） |
| 共起（`_record_cooccurrence(memories, 新しい id)`） |
| 要約・内省（背景タスクへ） |

**通す経路を変えない。** これが本課題の前提である。

## 3. 決めたこと（2026-09-09・6つとも確定）

### 大元：**主LLM は調べものと同じ扱い**

`_lookups` の器に `action="主LLM"` として載る。版・つなぎ・ブロック・世代の規則を、調べものと
同じものを使う。**新しい機構は作らない。**

器は既に「その場で終わるもの」（`recall`・`see`・`look`）と「投げっぱなし」（`deferred`）の
両方を載せている。外から見れば**すべて QC へ返る**という同じ形で、違いは `_run_lookup` の中
だけである。主LLM もそこへ並ぶ。

### ① 版は書く。ただし**結果は載せない**

投げるときに版を書き（`N番：主LLM を起動中`）、返ったときに版を書いて前の版を `改訂` で畳む。
**返りの中身は版に載せない。**

`see` が既に同じ形である。

> 版には結果を載せない。見たことは `_run_camera` が鎖の外へ独立した記録として書いており
> （**会話の「自分が答えた」と同じ位置**）、版にも載せると同じ出来事が2件になって、想起で
> どちらも上がり W の枠を食う。求めの状態としては「何番が届いたか」だけあればよい。

主LLM の返りの中身は `_finish` が `自分が答えた：…`（役割 `答え`）として書く。**コメントが
名指ししている位置がそれである。** 版にも載せれば、同じ発話が2件になる。

### ② 投げたときの W を**持ち越す**

`memories`（想起した W）と `_w_id_map`（12桁 → 完全な id）を、**主LLM の返りと一緒に運ぶ**。
「出す反復」では想起し直さない。

理由は2つある。

- **共起**は「その反復で一緒に活性した記録の集まり」なので、**主LLM が実際に見た W** でなければ
  意味がない。想起し直すと、主LLM が見ていない記録と共起させる
- **申告**（`memory_verdicts`）は W に印字された12桁で返るので、その W を作ったときの対応表で
  ないと引けない

**求めの寿命の状態に頼らない。** 版の content が「3件飛んでいても求めの状態はひとつ」と書く
とおり複数が同時に飛ぶので、主LLM が飛行中に別の完了が届けば `_w_id_map` は上書きされる。
12桁で当たってしまえば、申告が黙って別の記憶へ適用される。**同梱すれば、途中で何が起きても
壊れない。**

### ③ つなぎは**いまの規則のまま**

投げる瞬間のつなぎ（`effort != "low"` かつ材料が届いた反復でないとき）と、遅いときの見張り
（`lookup_slow_seconds`＝既定 5.0 秒で「まだかかっている」）の**両方を効かせる**。

`effort=high` は10秒近くかかるので両方出るが、それでよい。低い `effort` は実測 0.8〜3.6 秒で
返るので、投げる瞬間のつなぎは出さない（かえってテンポが悪くなる）。

### ④ 情動・機器のブロックは**そのまま効く**

主LLM を飛行中に数えれば、既存の仕組みがそのまま掛かる。

> **調査中は完了キューだけを待つ。** 飛行中の調査があるあいだに情動や人の出入りで別の連鎖を
> 始めると、1つの求めの途中に別の話が割り込む。…QA・QD は**消費せずキューに残す**ので、
> 調査が終われば順に処理される（取りこぼしではなく待たせるだけ）。

**代償も一緒に伸びる。** drive の発火と人の入退室への反応が、主LLM の待ち時間ぶん遅れる。

### ⑤ 「出す反復」は数えず、**主LLM の返りで反復をリセットする**

`_iterations`（上限 既定5）は、**軽量LLM を回した反復だけ**を数える。さらに、**主LLM の返りを
受けた時点で 0 に戻す**。

理由：**主LLM が調査結果を見て「足りない」と判断したなら、それは新しい一巡である。** 上限は
暴走防止の安全弁であって、主LLM が材料を見たうえで再度調べることを止めるためのものではない。

### ⑥ 追加の歯止めは**置かない**

リセットで深さの上限は無くなるが、歯止めは2つ残る。

| 歯止め | 中身 |
|---|---|
| **語の重複禁止** | 「この求めで一度調べた語は、二度と調べない」。`_lookups` は `_finish` と打ち切りでしか空にならないので、同じ語では回れない |
| **毎往復の調停** | **主LLM は自分が投げた結果を直接受け取らない。** 完了はいったん軽量LLM が受け、`light`（答えて閉じる）・`action`（次を投げる）・`full`（主LLM を投げる）を選ぶ。**1往復ごとに「もう答えてよいか」を判断する機会がある** |

**残る不確実性：** 軽量LLM は W しか見ず、「何往復したか」を見ていない。リセットすると
`[反復] N/M` の表示が常に小さい値へ戻るので、**「もう長い」という手がかりが軽量LLM から
消える**。実機で往復数を見るまで、これが効くかは分からない。

### ⑦ QC が運ぶ形（① 〜 ⑥ から従属）

QC の要素は現在 `(語, 結果, 意図id, 種別, 番号)` のタプルで、**結果が文字列**である。主LLM の
返りは `TurnResult`（`stop_reason`・`text`・`tool_calls`・トークン数）に加え、②で決めた
`memories` と `w_id_map` を運ぶ必要がある。**タプルでは位置で読む場所が増えすぎる**ので、
段は（`Lookup`）と同じく**器にする**。

種別は現在 `完了`・`進捗` の2つで、`_intake` が捌き分けている。**`決定` を足す。**

### h-い でやったこと（2026-09-09）

QC の要素を5つ組から `Completion` へ変えた。種別は `完了`・`進捗`・**`決定`**の3つで、
`決定` は `TurnResult` と、投げたときの `memories`・`w_id_map` を運ぶ。

**積む側6か所・読む側2か所**を名前で読む形へ移した。位置で読む書き方は0件になった
（`tests/test_completion_record.py` が確かめる）。**この段では `決定` を積む者はまだ居ない**
——型を広げただけで、挙動は変えていない。

## 4. 完了条件

- `_iterate` が「決める反復」だけを回し、行数が減る（**数字で示す**）
- `_iterations` が軽量LLM を回した反復だけを数え、**主LLM の返りで 0 に戻る**
- **版に主LLM の返りの中身が載らない**（`see` と同じ形・対で確かめる）
- **主LLM が飛行中に別の完了が届いても、申告が正しい記憶へ当たる**（テストで再現する）
- **`自分が答えた：…`・やりとり・共起が、いまと同じに書かれる**（対で確かめる）
- 主LLM が飛行中でも、人に話しかけられたら打ち切れる（世代で捨てる）
- `ruff` / `mypy` / 全体テストが緑
- `課題8` の 環-f-ろ を、本課題へ吸収したものとして書き換える
- 実装後、`用語_略語一覧` へ「決定」（QC の種別）を追記する

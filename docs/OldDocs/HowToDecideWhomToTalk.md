# 「誰と話すか決める構造」設計方針

## 位置づけ
自発発話（share_memory 等の社会的 desire）の発火時、その場にいる複数人
（present_ids）の中から「今、誰に話しかけるか」を決める構造。現状この意思決定は
存在せず（会話中の話者 current_speaker_id はあるが、自発発話で相手を選ぶ仕組みが
無い）、複数人環境での自発発話の前提として必要。pending_speech（Issue D）はこの
構造の上に乗る。本構造は複数人対応の基礎部品であり、pending 以外からの参照も
想定して独立に設計する。

## 適用範囲
- 社会的欲求（他者への発話）に限る。独り言（自己発話）は対象外（別Issue）。
- target=NULL の pending（誰でも話したい）も社会的欲求として本構造で扱う
  （その場の誰かに向けて発せられる。独り言ではない）。

## 前提（実環境で確認済み）
- present_ids: PersonMemoryManager.get_present_ids()（AGENT_SELF は含まない）。
- 関係性: PersonRegistry が per-person RelationshipTracker を管理。person_id ごとに
  trust / intimacy を独立取得できる。
- pending 鮮度: pending_speech の各行を DecayState で鮮度スコア化（Issue D）。

## 計算式

present_ids の各 person p について「話しかけたい度」を算出し、確率的に1人選ぶ。

### 1. 各要素の素の値
```
内容の強さ[p] = (target=p の pending の鮮度スコア合計)
              + (target=NULL の pending の鮮度スコア合計)   ← 全員に共通加算
関係性[p]     = f(intimacy[p], trust[p])
```
- pending 鮮度スコアは DecayState.score() による。複数 pending は合計で集約
  （話したいことが多く溜まっている相手ほど強い）。
- target=NULL は特定 person に紐づかないため、present 全員の内容の強さに同じ値を
  加算する（「誰でも話したい」状態を、その場全員への底上げとして表現）。この加算は
  **正規化の前**に行う。NULL が大きいほど個人差が相対的に縮む。

### 2. 正規化（present 内のシェアに変換）
各要素を present_ids 全体の合計で割る。
```
norm_内容[p]   = 内容の強さ[p] / Σ_q 内容の強さ[q]
norm_関係性[p] = 関係性[p]     / Σ_q 関係性[q]
```
合計で割ることで各要素は present 内シェア（0〜1, 総和1）になり、単位の異なる
内容と関係性を同じ土俵で合成できる。

### 3. 合成（重み付け）
```
話しかけたい度[p] = norm_内容[p] × w_content + norm_関係性[p] × w_relation
```
- w_content, w_relation は設定値。ただしコード内にデフォルト値も持つ
  （_float_env(name, default) パターン。環境変数が無ければデフォルトで動く）。

### 4. 選択（確率選択＋温度）
```
確率[p] ∝ 話しかけたい度[p] ^ (1 / T)
```
- 温度パラメータ T は最初から用意する。デフォルト T=1（完全比例）。
- T=1（デフォルト）では話しかけたい度に完全比例した確率で選ぶ。
- T を上げると分布がなだらかになり、弱い相手も選ばれやすくなる（揺らぎ増）。
- この確率で present_ids から相手を1人選ぶ。

## 選択後の扱い
選ばれた相手 p に対して、その相手向けの pending（target=p および target=NULL）を
話す。複数 pending は鮮度順に、pending 専用上限（独立設定値）まででまとめる。
（pending 発話の詳細は Issue D 本体で定義）

## 設定値（環境変数化・コード内デフォルトも保持）
- w_content … 内容の強さの重み
- w_relation … 関係性の重み
- T（温度） … 確率選択のなだらかさ。デフォルト 1.0（完全比例）
- 関係性算出 f(intimacy, trust) の係数（必要なら）

## 設計判断の記録（なぜこうしたか）
- 確率選択（案B）を採用: 「少し揺らがせたい」要件。最も話しかけたい相手が
  ほぼ選ばれるが、確率なので時々他の相手も選ばれる自然な揺らぎ。
- 正規化を合計で割る: 単位の異なる内容・関係性を present 内シェアに揃え、
  確率分布に直結させるため。
- NULL を正規化前に全員加算: 「誰でも話したい」を特定個人への偏りでなく、
  その場全体への話しかけ衝動として表現するため。
- 温度はデフォルト完全比例: 揺らぎは確率選択で既にあるため、まず完全比例で
  始め、必要時に温度で調整できる余地だけ用意する。

## capabilities への反映（実装時に対応）
本構造を実装するモジュールの docstring 先頭（350字以内）に、「複数人がいる場面で
誰に話しかけるかを内容と関係性から決める」旨を簡潔に記す。これにより
collect_manifest_context() 経由で capabilities に反映され、エージェントが自己の
能力として認識できる。具体的な docstring 文面は Issue D の TDD 改造方針で指示する。
